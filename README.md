# Aplena

**按月看清个人财务事实，并预估下一步收支。**

Aplena 是一款本地优先的个人财务规划桌面软件。它把本月收入、支出、退款与冲减组织成可核对的月度结果，再用总览、历史趋势和规则投影回答两个问题：这个月实际发生了什么，下个月按现有规则预计会怎样。

它不是传统流水账，也不要求先建立长期计划。首次打开会以人民币作为本位币直接进入应用；你可以从一项本月收入或支出开始，之后再按需要配置下月预算和周期规则。

## 产品定位

### 为什么需要 Aplena

日常财务软件常把注意力放在每笔交易、账户余额或分类流水上，但真正影响长期决策的往往是月度结构：稳定收入能否覆盖必要支出与固定承诺，本月结余是否符合预期，以及现有周期规则会形成怎样的下月收支结果。

Aplena 以月份为基本工作单位，将真实结果、可选预算基准和历史变化放在同一套口径下。用户不必每天记账，也不需要为了看报表维护账户、商户或复式分录。

### 与传统记账的区别

```text
本月收入 / 支出 / 退款 / 冲减
                ↓
          月度执行与核对
                ↓
       总览 · 历史趋势 · 储蓄率
                ↓
      为下一个自然月配置预算
```

- 实际数据以月度项目下的可解释条目组成，不保存可随意修改的月度总额。
- 计划只提供比较基准；没有周期规则也能完整记录和查看实际财务结果。
- 下月预算只作用于下一个自然月，不改写当前月或历史月。
- Aplena 不提供云账户、银行同步、交易导入、备份恢复或可读导出。

## 围绕月份工作

### 总览

打开应用即可看到本月实际收入、支出、净结余与储蓄率，以及计划对比、重要偏差、分类结构和历史趋势。没有实际条目的类目和精确报表保持为空；“计划与实际”柱状图只在绘图层把缺失指标落在 `0` 轴，避免显示未定义，不会写入虚假实际数据。

### 月度执行

月度执行用于查看预算类目、创建仅属于所选月份的临时类目，并逐笔添加实际条目。支出可以追加退款，收入可以追加冲减；条目支持编辑和删除，临时类目也可连同其实际条目一起删除。当前月从主导航进入，历史月可从对应报告进入调整。类目没有待确认、已完成等生命周期状态。

每笔外币实际会保留原币金额、当次换算汇率、来源与参考日期。后续汇率更新不会回算已经发生的费用。

周期规则可单独开启“自动入账”，默认关闭，开启后从下个月生效。到约定日期，应用会直接写入可编辑、可删除的正式实际条目，并标注自动来源。已删除的自动条目不会在重开或再次检查时出现；若同一类目已有手动实际，应用会提示关联、跳过或另建一笔，由用户处理。

### 专项

旅行、装修等事项可建立独立专项，设置总预算，并把其中一部分明确分配到各个月份。未分配部分保留在项目预算池，不自动摊入月度预算。月分配与周期规则预算共同构成对应月份的预算；已经形成的月度快照保持冻结。

专项中的支出、退款与月度执行共用同一条实际记录。专项可按月份和明细组查看净支出，并分别显示未分配预算与“总预算减实际净支出”的剩余预算。跨月退款记在退款发生月；实际超出总预算仍可保存，归档后也可补录晚到事实。

### 配置下月预算

“配置预算”只面向下一个自然月。你可以按需要添加周期规则，用于自动生成后续月份的计划基准，并派生下月预计收入、支出、储蓄和储蓄率；专项的下月分配额也进入同一预算总额。页面将下月预算概览与支出类型占比并排展示；图表可翻转为内部滚动的精确数据，不会拉伸同一行。周期规则是增强项，不是开始使用 Aplena 的前置条件。

自动入账使用一次完整支付金额，周期仍按原规则的月数。多月均摊只表示月度预算负担，不表示每月都支付；这类规则开启自动入账时需明确首次支付日。应用在启动、回到窗口及运行期间检查当前月已经到期的记录；关闭应用时没有后台写入，重开也不会自动补造遗漏历史月份。外币使用已保存的汇率快照，缺失汇率时显示失败并允许补充后重试。

### 历史报表

历史报表按年份展开已有月份，并可进入任意月份查看分类、项目、储蓄率与趋势。报告中的“调整该月数据”和项目“调整条目”入口允许补录、编辑或删除用户实际条目；计划快照仍不会因后来修改预算、周期规则或汇率而变化。

## 产品原则与数据边界

### 本地优先

Aplena 是单用户、单账本的本地桌面应用，不需要登录，也不会把财务数据上传到云服务。网络只用于读取欧洲央行每日参考汇率，以及从 GitHub Releases 检查和下载软件更新；断网时仍可使用全部本地财务功能、本位币和已经保存的备用汇率。

首个版本使用受操作系统用户权限保护的本地 SQLite 数据库，目录与数据库相关文件限制为当前用户访问。数据库文件本身未做静态加密，因此不能把 Aplena 描述为端到端加密产品；建议在设备上启用 FileVault，并妥善保护本机账户。

### 稳定的财务口径

- 本位币默认人民币，可在尚未形成月度事实或专项预算前修改。
- 金额以固定两位精度保存，汇率保留八位精度。
- 计划快照一旦进入某个月份便保持冻结。
- 实际净额由增加条目减去退款或冲减条目实时派生。
- 无收入等零分母场景显示为不可计算，不制造无效比例。

### 清晰的功能边界

Aplena 关注个人财务事实、月度执行和预算投影，不提供账户余额管理、自由流水、商户系统、会计分录、银行同步或独立“财务分析”模块。详细分析已经融入总览和每个月的历史报告。

## 获取与使用

### 系统要求与下载

首发目标为 macOS 11 及以上版本。正式版本通过严格的 `vMAJOR.MINOR.PATCH` 标签构建；双架构远程流水线验证通过后，可在 [GitHub Releases](https://github.com/Morton-Li/Aplena/releases) 下载 Apple Silicon 与 Intel 安装包。安装首个包含 updater 的桥接版本后，后续稳定版可以由应用在后台检查，并在用户确认后下载、验签、安装和重启；当前公开的 `v1.1.3` 尚不具备该桥接能力，仍需最后一次手动安装桥接版本。

GitHub Actions 发行流程配置为使用项目的 “Morton Li” 自签名证书并校验证书指纹，同时使用独立的 Tauri updater 密钥验证更新包。两套签名不能互相替代；自签名证书不属于 Apple Developer ID 信任链，也未经过 Apple 公证，因此 macOS 仍可能在首次打开或更新后显示安全提示。本地自行构建的应用仅使用系统默认的 ad-hoc/linker 签名，普通开发构建也不会生成可发布的 updater 包。

### 第一次打开

应用没有启动向导。首次打开会默认使用人民币并直接进入总览；前往“月度执行”创建第一项收入或支出即可开始。若需要外币，在录入时直接选择支持币种，或先在“设置”更新官方参考汇率。

### 本地数据说明

数据保存在当前 macOS 用户的应用数据目录。Aplena 当前不提供内置备份、恢复或导出能力，卸载、清理应用数据或迁移设备前请先了解这一边界。开发期数据库与首个正式版数据库采用不同兼容边界，不能直接混用。
