## 本地优先与权限边界

选择 Tauri 2、React/TypeScript、Rust 和 SQLite STRICT + WAL，是因为产品服务于单用户、单账本的本地桌面使用，不需要云账户、协作或银行同步。应用没有本地 HTTP 财务服务；UI 通过明确注册的业务命令调用 Rust，不能自行执行 SQL。

Rust 集中承载金额、日期、计划确认和事务规则，领域层可脱离 UI 与数据库测试。SQLite 提供本地事务和显式版本化迁移；React 负责表单、表格、查询缓存和图表。代价是必须维护 Rust、平台 WebView、迁移与 WAL 恢复的工程边界。

网络仅用于欧洲央行参考汇率及 GitHub 软件更新。汇率失败或更新失败不应妨碍已有本地数据使用；不能把“本地优先”解释为整个应用永远不联网。

没有采用云端 Web + PostgreSQL，是因为账户和服务器维护与当前需求不匹配；没有让 React 直接使用 SQL 插件，是为避免绕过业务规则。相较 Electron，当前选择减少捆绑运行时并将本机能力集中在 Rust；原生 SwiftUI 会增加未来其他桌面平台的重写成本。

## 精确金额、纯日期与汇率来源

权威金额以整数分持久化，IPC 用固定两位小数字符串；输入超过两位直接拒绝。汇率保留八位精度。十进制换算和周期除法在最终本位币金额处舍入，并检查范围与溢出。

这避免 JavaScript 浮点数或 SQLite `REAL` 带来的不稳定金额，也避免“保存隐藏精度、界面只显示分”造成无法核对的差异。退款和冲减用正金额加 `DECREASE` 表达，实际净额允许为负。

纯业务日期使用严格公历 `YYYY-MM-DD`，月份使用 `YYYY-MM`，不先转成 UTC 时间戳。月末周期始终从原始日锚点计算，短月夹至月末后，后续长月恢复原始日，避免日期永久漂移。

已有月度项目、专项或借贷后，本位币锁定。仍允许切换时，已保存汇率在同一事务内换算到新本位币，不能删除仍被周期规则引用的币种。由旧汇率折算的结果标记原本位币和折算日期，不能伪装为新的官方参考报价。

实际条目保存原币、原金额、换算汇率及来源快照；后续汇率更新不回算历史。schema 9 的折算来源字段延续这一可解释性要求。

## 预算口径与月份冻结

同一周期费用可能表达长期月均负担，也可能表达某月整笔支付，因此保留两种确认模式：

- `AMORTIZED`：有效日期与月份相交时计入完整月均额，不按有效天数比例摊销。
- `PAYMENT`：只在原支付日锚点对应的月份计入完整金额，并保存计划支付日。

下月预算的周期规则部分统一用月均等价金额，回答“按现有规则预计会怎样”；正式月度快照则按规则选择的模式计入。这两个数值用途不同，不应互相替代。

启动或跨月检查建立当前自然月上下文；本次会话初始化成功后，保存规则不自动回填，可显式补齐。重启或初始化错误重试仍会确保当前月。历史和未来的初始化必须显式执行，预览和浏览不写入；跨月关闭后不自动补造中间历史。

初始化以来源 ID 和月份幂等，规则批次与专项批次各自在事务内先验证再写入，不承诺整月跨批回滚；已有正式快照不覆盖。已有 `ACTUAL_ONLY` 容器可原位提升为 `PLANNED`，保留月度项目 ID 与实际条目。这样既能补齐计划，又不破坏迟到退款等事实的身份。

没有采用“每次打开任意月份都重算”，因为会污染历史和提前冻结未来；没有用项目名称去重，因为改名不能改变身份。空月不额外建立只表示“初始化过”的期间实体，重复检查必须安全。

## 实际条目优先，取消完整状态

实际必须由关联月度项目的 `ActualEntry` 解释，净额由增加减减少实时派生；不保存供用户任意修改的月度实际总额。条目日期必须属于父项月份，不能编辑后改挂到其他月度项目。

周期规则为可选增强。用户可创建 `MANUAL + ACTUAL_ONLY` 临时类目直接记录实际；`item_origin` 明确区分手动类目、规则快照与专项，不能只用空来源外键判断，因为删除规则后保留的历史快照也会失去来源引用。

旧完整状态模型已删除：不再存在 `MISSING`、`IN_PROGRESS`、`CONFIRMED_ZERO`、`FINAL`、确认时间及单项/批量确认命令。没有条目时实际为 `null`；有条目且净和为零时才是零。

取消状态是因为核对标记没有增加财务事实，却引入触发器、重开状态、筛选和报表分支。确认操作也不能复制计划额或创建零实际来“补齐”报表。

临时类目允许在事务内连同实际条目删除；此命令不能删除预算快照。旧 `MIGRATED_AGGREGATE` 条目保持只读，不因文档整理而获得编辑权限。

## 下月预算与历史分析隔离

独立 `NextMonthGoal`、最低储蓄率和“剩余/最大承载能力”已经移除。把由规则计算的结果命名为外部目标，会让用户把没有独立约束的数值误解为可消费额度。

目标月份由后端确定为下一个自然月。现行投影组成是：周期规则月均等价金额、专项在下月的明确分配额、借贷下月到期的剩余利息费用；待还和待收本金单独展示。固定承诺占稳定收入比例、稳定收入覆盖倍数仍作为辅助指标。

当前月和历史分析读取被冻结的月度快照及实际事实，不读取动态下月目标。预计储蓄可为负；零分母不生成无效比例。年度储蓄率以全年净结余除以全年收入，不能平均各月储蓄率。

图表可为绘制需要处理缺失点，但精确数据必须保留 `null` 语义；显示层的零不能写成真实实际。界面布局和交互约定见 [产品与操作](product.md)。

## 自动入账与专项各自保存事实

自动入账按规则显式开启，默认关闭。开启及开启中的规则版本修改从下月生效；关闭立即停止，当前结束日也会立即阻止超出结束日的未入账发生。策略版本冻结名称、类别、模式、有效日期、币种、完整金额、周期和支付锚点，避免编辑规则改写本月执行含义。

月均预算不等于实际现金：多月均摊规则在约定日期按原周期生成完整金额，不把均摊额当作每月支出。应用只检查当前自然月已到期记录；没有关闭应用后仍运行的后台记账进程。

稳定规则 ID 与月份形成唯一发生槽。入账、月度容器与发生记录共同提交；`POSTED`、`SKIPPED`、`DELETED` 都消耗该槽，删除实际不会自动重建。同月已有手动事实时先登记冲突，由用户关联、跳过或另建，不能按相同金额猜测重复。

专项总预算与月分配分别表达项目额度和月份计划。未分配池不自动均摊或滚动；实际超支仍是应当保存的事实。分配形成正式快照后冻结，不能靠项目改名、预算修改或汇率更新回写。

专项与月度执行共用实际条目，按发生月归属并只聚合一次；跨月退款记在退款月。未分配预算和“总预算减实际净支出”的剩余预算含义不同，必须分开。归档保留事实，也允许补录晚到支出、退款和纠错。

## 借贷本金独立于收入与支出

借入与借出均使用独立合同，可完整记录发生日，也可从期初剩余本金开始跟踪。期初余额不补造过去现金流；追加借入或借出按实际日期形成本金现金流。

本金只影响借贷余额与现金净额，不进入收入、支出或储蓄率。借入利息费用记固定承诺支出，借出利息费用记浮动收入。现金净结余不是账户余额。

日、月、季、年分期按原始日锚点计算，不推断节假日顺延；等额本金/本息使用显式每期利率，不猜测年化换算或实际天数计息。特殊约定用手动逐期计划，本金尾差落在最后一期。

计划到期不自动生成还款。实际本金、利息、费用先预览分配再保存，计划版本、实际分配和关联月度条目保持可追溯；月度页不能直接改写借贷关联金额。

纠正历史还款或追加本金后，若有效计划未还本金与真实剩余本金不一致，显示“计划待核对”并暂停相关预测，现金事实仍正常展示。系统不猜测新日期或自动改写约定金额；用户核对分配或重排后恢复预测。

这避免重复安排已归还本金，或让后续计划悄悄改变历史。与同一借贷相似的周期规则仍须由用户显式处理，不按名称和金额自动关联。

## 数据保护与发行信任

数据库、WAL、SHM 当前未静态加密。Unix 平台通过目录 `0700`、数据库相关文件 `0600` 保护，并收窄前端能力；文件权限不能抵御已获得同一用户或管理员权限的读取者。不能将其描述为端到端加密。

暂不引入 SQLCipher，是因为密钥存储、错误密钥处理、迁移、崩溃恢复与真实发行包验证尚需独立设计。未来加密应在隔离数据和真实平台上证明失败时拒绝访问、不会回退明文或静默新建库，并提供可恢复迁移；不采用固定密钥或自创页面加密。

更新的 minisign 验证与 macOS 代码签名承担不同职责：前者验证更新包字节，后者验证应用身份。当前 macOS 安装器还校验 Bundle ID、版本、架构和固定证书指纹，在同设备临时目录准备新包后只执行原子交换；失败不做破坏性回退。

启动可以自动检查更新；下载、安装与重启由用户触发。自签名证书不代表 Apple Developer ID 信任链或公证，不能承诺不出现系统安全提示。未包含 updater 的旧客户端需要一次手动安装；公开版本状态应在发行时重新核实，不固定为文档中的历史版本号。

updater 密钥和代码签名证书分别管理。丢失旧 updater 私钥后，既有客户端不能直接信任新密钥；密钥轮换须提前以旧密钥签署桥接版本，否则需要手动安装。候选包、本地临时密钥及模拟端点测试不能代替正式标签流水线与真实升级验证。

## 后续变化

静态加密、云同步、备份恢复、交易导入、可读导出和其他平台正式发行都不因本页列出而成为已有能力。引入这些功能，或放宽更新验证、历史冻结与本金口径时，应先记录新的取舍，再同步对应实现文档和验证证据。

继续维护现有正式迁移历史，不为整理文档而重写已发布迁移；旧预发布库的受控转换与产品内备份恢复是不同能力，操作边界见 [开发与发行](development.md)。
