# ADR 0004：分精度金额、日级日期与单次舍入

- 状态：接受，2026-08-23 取代四位金额/月级日期决策
- 决策范围：金额、汇率、日期和跨层协议

## 背景

个人财务产品的权威金额以分足够。旧四位金额增加 UI、迁移和解释成本。计划只保存月份又无法正确表达月底支付与精确结束。JavaScript `number` 和 SQLite `REAL` 都不适合作为财务事实边界。

## 决策

### 金额

- `Amount` 权威精度两位，缩放因子 100，输入超过两位直接拒绝；
- 计划金额与实际条目金额必须非负，实际条目还必须严格大于零；
- 实际净额和偏差使用 `SignedAmount`，允许负数；
- SQLite 使用 64 位整数，IPC/JSON 使用固定两位字符串；
- 任何汇率乘法和周期除法使用十进制，只在最终本位币金额执行一次 `ROUND_HALF_UP`；
- 所有转换与加总都检查溢出。

汇率保持八位小数和 100,000,000 缩放因子，因为汇率输入需要高于分的精度。

### 日期

- `CalendarDate` 使用严格 `YYYY-MM-DD`，校验公历和闰年，不附时区；
- `YearMonth` 使用 `YYYY-MM`，数据库锚点为月首；
- 计划开始/结束、PAYMENT 计划支付日和实际发生日都用日级日期；
- 前端传递原始日期字符串，不把纯日期先转换为 UTC 时间戳。

### 旧数据转换

预发布 schema 3 曾用整数商和余数把旧四位缩放金额 `ROUND_HALF_UP` 为分，避免 SQLite `REAL`，并把旧月锚点作为日级日期保留。首个公开版发布前，这段预发布转换已压缩进正式 schema 1；正式基线直接使用分和日级日期，不执行历史转换。

## 后果

- UI、IPC 和测试期望统一为 `0.00`；
- 用户不能保存三位小数，避免界面显示与权威值不一致；
- 日级规则可重现 1 月 31 日、闰日和月中结束；
- 退款不需要负金额输入，由 `DECREASE` 条目表达；
- 数据库迁移必须验证旧值边界、舍入、空值和零值。

## 被否决方案

- 保留四位权威金额但只显示两位：用户无法解释隐藏精度；
- 使用浮点数：不能给出稳定十进制舍入；
- 接受任意精度后静默舍入：输入错误不透明；
- 所有日期只存月份：支付锚点和精确结束日丢失；
- 使用带时区时间戳表达纯日期：增加无价值的日期漂移风险。
