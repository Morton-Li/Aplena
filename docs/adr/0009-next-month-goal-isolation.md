# ADR-0009：下月目标与当前、历史报表隔离

状态：接受

## 背景

旧实现把目标月份与最低储蓄率放在全局设置中，并让当前月、历史月分析和承载力共同读取它。这样修改一个前瞻目标会改变既有月份的展示口径，也让周期规则看起来像独立的长期规划功能。

## 决策

1. 新增独立 `NextMonthGoal` 聚合和“目标”页，目标月份始终由后端计算为下一个自然月。
2. 客户端只能修改 0–10000 基点的储蓄率，不能指定当前月、历史月或任意未来月。
3. 下月承载力读取 `NextMonthGoal + PlanItem + ExchangeRate`；当前月和历史分析只读取冻结 `MonthlyItem + ActualEntry`。
4. 周期规则迁入“目标”页，作为下月规划的可选增强，不形成独立长期规划页面。
5. 新建或修改周期规则不自动初始化当前月。应用只在启动时自动补齐当前自然月，其他补齐必须显式执行。
6. 跨月后旧目标不转为报表目标；系统为新的下一个自然月建立默认 20% 储蓄率。

## 后果

- schema 5 新增 `next_month_goal`，从旧 `settings.minimum_savings_rate_bp` 迁移当前值，并从 `settings` 删除目标月份和储蓄率；
- 总览和历史报表不再展示动态“最低储蓄目标”，储蓄率完成度只比较该月冻结计划；
- 设置页只管理本位币和汇率；
- 旧 `/plans` 路由兼容跳转到 `/goals`；
- 自动测试必须证明保存目标或周期规则不会改写当前月及历史快照。
