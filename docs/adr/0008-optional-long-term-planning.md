# ADR-0008：长期计划是可选增强，月度实际可独立录入

状态：接受

## 背景

原实现要求全局实际录入先选择长期计划，即使用户只想记录本月已发生的收入或支出，也必须先建立周期计划。这把增强分析所需的计划基准错误地变成了基础使用门槛，并使空总览只能引导用户创建长期计划。

## 决策

1. 月度实际是主路径。用户可直接创建 `MANUAL + ACTUAL_ONLY` 月度项目并写入实际条目。
2. 长期计划保留为可选增强，用于自动生成周期快照、计划偏差和财务承载能力。
3. `monthly_items.item_origin` 区分 `PLAN_LINKED` 与 `MANUAL`。不能只依靠可空 `source_plan_item_id`，因为删除计划后保留的脱离快照也没有来源引用，但仍不得接受新条目。
4. 手动项目参与实际收入、支出、净结余、分类结构和趋势，不把零计划容器解释为真实计划，因此偏差与完成率为未知。
5. 没有长期计划时承载能力显示为未启用，不展示容易误解的零值。
6. 后续由 ADR-0009 将该能力统一表述为“目标”页内的可选周期规则；它不是独立的长期规划页面。

## 后果

- schema 4 追加 `item_origin`，已有记录默认迁移为 `PLAN_LINKED`；
- 全局录入默认“本月项目”，关联长期计划是次级可选模式；
- 已删除计划留下的脱离快照继续拒绝新条目，手动项目可以持续维护；
- 产品、UX 与分析投影均需识别创建来源。
