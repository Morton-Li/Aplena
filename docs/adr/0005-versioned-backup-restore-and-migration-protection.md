# ADR 0005：版本化备份、安全恢复与迁移前保护

- 状态：Accepted
- 日期：2026-08-23

## 背景

Aplena 的月度快照是历史事实。SQLite 使用 WAL 时，直接复制主数据库文件可能遗漏仍在
WAL 中的已提交页面；恢复未经验证的归档也可能让损坏、未来版本或恶意路径覆盖当前数据。
CSV 适合人工查阅，但不能表达全部恢复契约。

## 决策

1. 完整恢复格式使用扩展名 `.aplena` 的 ZIP 归档，格式版本为 `1`；归档只允许
   `manifest.json` 和 `database.sqlite3` 两个普通文件。
2. 数据库副本由 SQLite `VACUUM INTO` 创建。这是事务一致快照，不依赖复制 WAL 或 SHM。
3. 清单记录备份格式、应用版本、SQLx schema 版本、UTC 创建时间、数据库大小、SHA-256、
   四表记录数、月份范围和非敏感设置摘要。
4. 恢复检查拒绝绝对路径、路径穿越、目录、符号链接、重复或额外条目、超限归档、不合理
   记录数、异常压缩比、非 SQLite 文件、校验和不符、未来格式或 schema。
5. 备份数据库只在应用私有临时目录展开；随后在临时副本上执行向前迁移、SQLite
   `quick_check`、`integrity_check`、外键检查、核心对象检查、领域不变量检查和月度分类
   聚合重算。预览明确对照当前数据与备份的设置、四表记录数和月份范围。
6. 检查结果只向前端返回文件名、摘要和 15 分钟有效的一次性令牌，不返回路径。恢复要求
   勾选确认并输入“恢复”；执行时再次核对归档哈希。
7. 替换前先为当前数据库创建 `.aplena` 恢复点。所有业务操作与恢复通过公平读写门控协调；
   恢复独占门控后 checkpoint、关闭连接池、在同一文件系统原子换名、重开并复核。失败时
   换回原数据库并重开。
8. SQLx 迁移只能追加。启动发现现有数据库有待执行迁移时，先生成一致恢复点；恢复点失败
   则拒绝迁移。全新数据库和已是最新 schema 的数据库不生成冗余恢复点。
9. CSV 导出生成 `settings.csv`、`exchange_rates.csv`、`plan_items.csv` 和
   `monthly_items.csv`。金额和汇率是固定小数字符串，NULL 实际为空、零实际为 `0.0000`；
   枚举同时导出稳定代码和中文标签，文本单元格防范公式注入。

## 安全边界

- 系统文件选择器只在 Rust 命令中调用；前端没有任意路径读写命令或文件系统权限。
- 临时目录权限在 Unix 上为 `0700`，备份与 CSV 文件为 `0600`；成功和失败均由临时目录
  守卫清理。
- 归档和数据库都有显式大小上限；任何失败都返回稳定错误代码，不暴露本地完整路径、财务
  内容或底层 SQL。
- `.aplena` 当前是完整性保护格式，不是加密格式。加密结论见 ADR 0006。

## 后果

- 数据库生命周期由单一服务门控管理，备份可以和普通 WAL 写入并发，恢复必须独占。
- 恢复预览和最终恢复会重复检查同一文件，增加少量 I/O，并通过一次性令牌与前后哈希核对
  降低检查后文件被替换的风险。
- CSV 可读、确定且安全，但明确不作为导入或无损恢复格式。
- 恢复点占用本地磁盘；MVP 不自动删除恢复点，避免无授权的数据销毁策略。

## 验证

集成测试覆盖四表往返、设置和聚合一致、孤立快照、NULL/0、WAL 并发、重复备份、一次性
令牌、并发恢复、迁移成功和失败、归档篡改、未来版本、路径穿越、符号链接、重复条目、
压缩炸弹、大小上限、CSV RFC 引号、Unicode、稳定顺序和公式注入。
