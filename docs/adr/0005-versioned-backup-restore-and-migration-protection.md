# ADR 0005：版本化完整备份、兼容恢复与迁移保护

- 状态：接受，2026-08-23 修订为格式 2
- 决策范围：本地数据库备份、恢复、CSV 和前向迁移

## 背景

SQLite WAL 数据库不能靠复制主文件保证一致性；恢复是不易撤销的高风险动作。schema 3 新增实际条目、日级日期与分精度，还必须支持旧格式 1 备份。CSV 缺少约束与事务，不能承担恢复责任。

## 决策

### 完整备份

`.aplena` ZIP 当前 `format_version = 2`，包含：

- 通过 SQLite 备份机制取得的一致数据库快照；
- manifest：应用版本、schema 版本、创建时间、大小、SHA-256、五张业务表计数、设置和月份范围。

数据库迁移前也创建同类恢复点，写入后重新校验文件与摘要。

### 恢复

恢复分检查和执行：

1. 将用户文件视为不可信，拒绝绝对/穿越路径、链接、重复文件、未知项、压缩炸弹和异常记录数；
2. 校验 manifest、大小和 SHA-256；
3. 格式 2 验证当前五表；格式 1 在隔离副本执行追加迁移后再验证；
4. 验证 schema、外键、表、索引、触发器和业务不变量；
5. 返回与文件指纹绑定的一次性确认 token 和前后摘要；
6. 用户输入确认短语后串行执行；先备份当前库，再原子替换；
7. 任一步失败保持当前数据库可用。

未来格式或未来 schema 一律拒绝，应用不尝试降级写入。

### CSV

CSV 导出五张业务表，金额两位、汇率八位、代码稳定并附中文标签。月度实际列明确命名为派生实际，另含条目数和确认状态；实际条目单独输出。使用 RFC 4180 引号和公式注入防护。

CSV 没有 manifest、校验和、外键、触发器或原子恢复协议，因此永远不作为恢复输入。

## 兼容边界

- 格式 1：允许检查、隔离前向迁移和恢复；旧摘要按原四表口径比较，恢复后返回当前五表摘要；
- 格式 2：当前原生格式；
- 格式 >2 或 schema 高于应用：拒绝；
- 已发布数据库迁移不可修改，只追加。

## 后果

- 备份恢复测试必须覆盖 WAL 并发、旧格式 1、一次性 token、文件变更、攻击面和五表往返；
- 恢复 UI 必须明确展示是否进行了迁移和当前/备份摘要；
- 备份文件本身可能包含敏感财务数据，用户需妥善保存；
- 数据库加密是 ADR 0006 的独立发布门，不能由备份机制替代。
