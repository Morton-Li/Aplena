# ADR 0010：临时类目与无状态的月度实际

- 状态：接受
- 日期：2026-08-31
- 取代：ADR 0007 的完整状态与确认语义

## 背景

月度类目的 `MISSING`、`IN_PROGRESS`、`CONFIRMED_ZERO`、`FINAL` 状态和单项/批量确认增加了独立生命周期，但没有增加实际财务事实。实际金额已经由条目完整表达；将“是否核对”绑定在类目上还会影响报表、筛选、数据库触发器和编辑后的重开行为。

同时，全局“添加实际条目”把类目创建、计划关联和实际录入混在一个对话框中。用户需要的是先补充一个仅属于本月的非预算类目，再在其上下文中维护实际条目。

## 决策

- 月度类目不具有确认或完成状态；删除 `actual_confirmed_at`、状态枚举、确认命令、筛选和报表状态字段。
- 没有条目时派生实际为 `null`；有条目时以增加减减少的净额为准，净额可为零或负数。
- 月度页全局入口只创建 `MANUAL + ACTUAL_ONLY` 临时类目，实际条目从详情抽屉创建或编辑。
- 临时类目可删除。Store 必须在事务内验证其为无计划来源的 `MANUAL + ACTUAL_ONLY`，删除其实际条目后再删除类目；预算快照拒绝该命令。
- 实际录入日期在当前执行月等于自然月时默认当日，否则默认月首。条目模态和删除确认位于详情抽屉上层，抽屉在操作期间保持挂载。
- schema 1 保持不可变，以 schema 2 追加删除状态列和三个条目变更重开触发器。

## 后果

- 月度执行表不再显示状态列，也没有“确认项目已完成”或批量确认操作。
- Dashboard、历史和分析只表达实际存在性、计划基准和类目数量。
- 无条目不能解释为零；零实际必须由实际条目的净和自然形成。
- 删除临时类目是不可撤销的级联业务操作，UI 必须显示实际条目数量并二次确认。
- ADR 0007 中实际条目、退款/冲减、计划外预算快照和原位提升的决策继续有效。
