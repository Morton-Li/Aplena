# ADR-0013：自动实际记录与跨月专项

- 状态：Accepted
- 日期：2026-10-07
- 数据库：schema 6

## 决策

周期计划、正式实际和专项预算分别表达不同事实。周期规则的月均额是预算基准；开启自动入账后，到约定日期才生成一次完整支付金额的实际条目。专项总预算是独立额度，只有明确分配到月份的部分进入月预算；专项预算本身不生成实际。

### 自动入账

- 开关按周期规则保存，缺省关闭。开启及开启状态下的规则修改从下个月生效；关闭立即停止未执行记录。
- 每月规则默认次月 1 日，可指定首次日期；`PAYMENT` 沿用原支付日期。多月 `AMORTIZED` 需明确首次支付日，以完整金额每隔原周期月生成，不能把月均预算当作每月现金。
- 策略版本冻结规则名称、类别、计入模式、有效日期、原币完整金额、币种、周期和支付锚点。当前有效版本不被本月规则编辑回写，未来尚未生效版本可更新。
- 只检查当前自然月且已经到期的普通支付。启动、窗口回到前台及运行期间触发；没有独立后台进程，长期关闭后不自动补造中间历史月。保存汇率可支持离线使用，缺失汇率显式失败且可重试。
- 以稳定规则 UUID 与月份作为唯一发生槽。实际插入、月度容器及发生记录在同一事务提交；重复、并发检查安全。`POSTED`、`SKIPPED` 和 `DELETED` 均消耗该槽，删除实际不会自动重建。
- 同月已有手动实际时登记 `CONFLICT`，不按金额猜测。用户可关联一条已有记录、跳过或另建一笔；失败和冲突不会伪装为成功。
- 自动条目标注 `AUTOMATIC`，与用户条目一样可编辑、删除。编辑保留原汇率快照，删除在同一事务留下发生槽墓碑。停止或删除规则不会删除历史事实。

### 专项

用户入口称“专项”，持久化实体为 `SpecialProject`。它适合旅行、装修等多明细、可能跨月的事项，保留现有五种财务类别，首期专项只使用三类支出。可选明细组用于项目内用途，不新增财务类别。

- 总预算使用创建时的本位币，并因此锁定本位币。所有月分配合计不能超过总预算；实际超支允许保存。
- `SpecialAllocation` 明确指定月份、支出类别和金额，同一专项、月份、类别最多一条。未分配预算不自动均摊、滚动或计入正式月预算。
- 当前月保存分配会形成正式快照；未形成快照的未来分配可编辑、删除。一旦初始化为月度快照，分配和快照都冻结，不能通过项目改名、总预算修改或汇率更新重写历史。
- 每个专项、月份、类别只有一个规范月度容器，来源为 `SPECIAL_PROJECT`。无分配也可记实际，此时为零计划的 `ACTUAL_ONLY`；后来补入允许的分配可原位提升，保留 ID 和全部条目。
- 实际只有 `ActualEntry` 一个来源，专项归属由月度父项导出。专项页和月度执行显示同一条记录，月度总览与历史只聚合一次。
- 支出与退款按各自发生月归属。原币、金额、汇率、来源和观察日固定在条目上；后续汇率不回算。项目净额为支出减退款，允许负值。
- 未分配预算等于总预算减月分配；净剩余预算等于总预算减实际净支出。二者分别显示，不能互作余额。
- 归档保留月分配和实际事实，也允许显式补录晚到支出、退款及调整已有实际；恢复后继续分配。

### 统计协作

下月投影汇总周期规则的月均等价支出与专项在下月的明确分配额，分别显示构成并合计一次。专项总预算及未分配池不进入月度总额；自动实际不修改预算。只有正式计划来源具有偏差基准，专项的仅实际容器不制造零预算偏差。

## 验证边界

只追加 `0006_budget_specials.sql`，合成 schema 5 数据迁移后应保留 ID、金额、汇率快照、实际和旧约束，已有规则自动开关保持关闭。业务测试注入日期，不依赖墙上时钟；真实应用冒烟使用全新 `APLENA_SMOKE_DATA_DIR`，不接触个人财务数据库。此变更不增加备份、导入或导出能力。
