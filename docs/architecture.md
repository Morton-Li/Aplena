# 架构与领域规则

本文描述当前代码的分层、财务口径与事务边界。操作流程见[产品与使用](product.md)，表结构和迁移见[数据库](database.md)，设计取舍见[设计决策](decisions.md)。

## 代码分层

Aplena 是单用户、单账本的本地桌面应用：Tauri 2 + Rust + SQLite/SQLx，前端使用 React、TypeScript、Vite、TanStack Query 和 ECharts。

```text
React 页面 → Tauri IPC → FinanceService → 纯领域规则
                              ↓
                         SQLite Store

软件更新 → 独立 SoftwareUpdateService → 下载验签与 macOS 安装器
```

| 位置 | 职责 |
|---|---|
| [`crates/pfcm-domain/src`](../crates/pfcm-domain/src) | 金额、日期、类别、规则计入、预算投影与分期计算；不依赖 Tauri、数据库、文件系统或当前时间 |
| [`src-tauri/src/application`](../src-tauri/src/application) | DTO、校验、当前日期、事务编排、月度分析、专项、自动入账、借贷 |
| [`src-tauri/src/infrastructure`](../src-tauri/src/infrastructure) | SQLx 连接池、迁移、Store、文件权限与持久化模型 |
| [`src-tauri/src/application_updates`](../src-tauri/src/application_updates) | 更新状态机、版本/端点校验、下载验签与原子安装 |
| [`src-tauri/src/lib.rs`](../src-tauri/src/lib.rs) | 数据目录、服务启动、IPC 注册与冒烟隔离保护 |
| [`src/features`](../src/features) / [`src/shared`](../src/shared) | 页面、表单、查询缓存、展示和共享 IPC 客户端 |

## 金额、汇率与日期协议

权威的录入换算、规则计入、借贷本息、月度分析与下月预算由 Rust 计算。IPC 金额和比例使用十进制字符串，不能以浮点数传递权威金额。

| 类型 | 约束 |
|---|---|
| `Amount` | 非负、两位小数、分单位 `i64` 可表示；输入超过两位直接拒绝。实际条目和借贷初始/追加本金要求严格大于零 |
| `SignedAmount` | 派生净实际、结余与偏差，可为负 |
| `ExchangeRate` | 大于零，规范为八位小数；表示一单位原币对应多少本位币；本位币对自身为 1 |
| `YearMonth` | IPC 为 `YYYY-MM`，数据库为 `YYYY-MM-01` |
| `CalendarDate` | 严格公历 `YYYY-MM-DD`，保持日历语义，不通过 UTC 转换 |

乘除使用 `Decimal`。规则快照换算与均摊在最终金额处按中点远离零舍入到分，避免先换算再均摊的双重舍入。借贷计划按各期本金/利息舍入，末期处理本金尾差，不能套用“整个计划只舍入一次”。

前端年度报告是现有计算边界中的一个例外：[`historyYearGroups.ts`](../src/features/history/historyYearGroups.ts) 从后端月度 DTO 用 `bigint` 分单位汇总金额，再从年度合计计算储蓄率与分类占比。它不重新计入周期规则，不平均月度百分比，也不持久化年度副本。图表可将金额转换为绘图数值，精确表格仍使用金额字符串。

## 聚合与类别

```text
周期规则 + 汇率 ──初始化──→ 月度计划快照 ──→ 实际条目
专项 + 月分配 ───────────→ 专项月度快照 ──→ 同一套实际条目
借贷 + 分期/收付/追加 ───→ 本金余额与现金流
               └────────→ 月度利息费用容器与受保护实际

月度项目 + 实际条目 ─────→ 总览、月报、历史 DTO ──→ 年报
有效规则 + 下月分配 + 借贷到期金额 ───────────────→ 下月预算
```

| 类别 | 方向 |
|---|---|
| `FIXED_INCOME` 固定收入 | `INCOME` |
| `VARIABLE_INCOME` 浮动收入 | `INCOME` |
| `ESSENTIAL_EXPENSE` 必要支出 | `EXPENSE` |
| `FIXED_COMMITMENT_EXPENSE` 固定承诺支出 | `EXPENSE` |
| `DISCRETIONARY_BUDGET` 自主性预算 | `EXPENSE` |

方向由类别派生，不能单独编辑。周期规则名称先做 NFKC 规范化、去首尾空白，再校验非空及唯一。

## 周期规则计入与下月投影

规则包含金额、币种、正整数月周期、开始/可选结束日期及计入模式。设原币金额为 `A`、汇率为 `R`、周期月数为 `P`：

| 模式 | 月度快照生成条件 | 计划额 |
|---|---|---|
| `AMORTIZED` 月均摊 | 有效日期与目标月有任意日交集 | `round(A × R ÷ P, 2)`；不按日折算 |
| `PAYMENT` 支付日确认 | 目标月与开始月的整月差非负且能被 `P` 整除，支付日在有效期内 | `round(A × R, 2)` |

`PAYMENT` 每次从原始开始日的“日”计算目标月支付日，短月夹到月末。例如 1 月 31 日的月付规则在 2 月取月末，3 月仍取 31 日。

下月预算固定面向下一个自然月，对该月有效的周期规则统一取月度等价金额 `round(A × R ÷ P, 2)`，与 `PAYMENT` 是否恰在该月付款无关。再加入专项明确月分配，以及有效借贷期次的利息/费用：借入费用为支出，借出费用为浮动收入。

```text
预计结余 = 预计收入 - 预计支出
含借贷预计现金净结余 = 预计结余 - 待还本金 + 待收本金
```

专项预算池、自动实际、独立储蓄目标均不进入投影；投影不建表。存在需核对计划的借贷时，返回 `LOAN_PLAN_REVIEW_REQUIRED`，不提供看似完整的下月结果。

## 月度快照与初始化

月度项目保存创建时的名称、类别、方向、模式、计划金额、本位币和可选支付日。后续修改规则、汇率或专项资料不会重写已有正式快照。

- `item_source` 区分 `PLANNED` 计划基准与零计划额的 `ACTUAL_ONLY` 实际容器。
- `item_origin` 区分 `PLAN_LINKED`、`MANUAL`、`SPECIAL_PROJECT`；借贷容器另由关联表识别，不能仅凭 `MANUAL` 判断可编辑性。
- 删除周期规则会使历史快照的来源外键置空，保留快照和实际。脱离来源的规则快照拒绝新增实际，既有可编辑实际仍可纠错。
- 仅实际容器在后续合法初始化/专项分配时可原位提升为正式快照，保持 UUID 与实际条目。

启动与跨月自动检查只确保当前自然月上下文。当前会话初始化成功后，规则保存不会触发本月补齐，用户可显式执行；重启或初始化错误重试仍会再次确保当前月。历史与未来读取不写入，显式初始化先预览候选、缺失汇率和警告，再确认写入。

规则初始化由应用服务操作门、数据库事务和来源唯一键共同保护：预先解析全部必要汇率，再新增快照或有条件地提升实际容器；重复执行保留既有快照，规则批次失败回滚。专项初始化使用独立事务，已成功批次不会因另一批失败而回滚；启动时即使规则缺汇率，也会尝试初始化专项。历史补录可使用临时汇率覆盖，不写回汇率表。没有候选项目的月份不会凭空保存一个“空月份”实体。

## 实际条目与汇率快照

每笔实际隶属一个月度项目，日期必须在该月，金额为正，通过 `INCREASE` / `DECREASE` 表示收入/支出增加及退款/冲减：

```text
净实际 = Σ INCREASE.amount - Σ DECREASE.amount
```

零条目时净实际为 `null`；有条目时可以为零或负。类目没有待确认、已完成等状态，也不保存可编辑实际总额。`ACTUAL_ONLY` 没有计划偏差基准。

实际额保存原币金额、币种、当次换算汇率、来源与参考日期。切换本位币产生的备用折算汇率另存原本位币与折算日期；写入实际时冻结同组依据。后续刷新汇率不回算旧实际，普通编辑沿用原快照。

`USER` 与 `AUTOMATIC` 条目可编辑/删除，不能改挂月度项目；`MIGRATED_AGGREGATE` 只读。日期同月由应用校验和数据库触发器双重保护。借贷关联条目由借贷命令统一维护，普通实际 CRUD 拒绝修改。

手动临时类目可以不依赖规则创建。删除命令只允许无规则来源的 `MANUAL + ACTUAL_ONLY`，并排除借贷容器，在同一事务删除类目和实际；正式预算快照及专项容器不走此入口。

## 自动入账

实现位于 [`automatic.rs`](../src-tauri/src/application/automatic.rs)。默认关闭；开启或重新开启从下月生效。开关与规则版本分开保存，当前生效版本保留，规则修改更新未来版本；但当前规则结束日会立即阻止超出结束日的未入账发生，关闭也立即停止。`AMORTIZED` 自动入账另需首次收支日；实际按完整单次金额及月周期发生，不按月均额入账。

应用启动、回到窗口及运行期间检查当前月已到期的发生日。无关闭时后台任务，不自动补造遗漏历史月份。当前月内因未打开应用而迟到的到期记录仍可生成。

| 发生槽状态 | 语义 |
|---|---|
| `POSTED` | 已创建自动实际或显式关联手动实际 |
| `CONFLICT` | 同类目存在非自动事实，或快照与冻结版本类别不符，须显式处理 |
| `SKIPPED` | 用户明确跳过，或执行版本金额为零而自动跳过 |
| `DELETED` | 已关联实际被删除，保留墓碑 |
| `FAILED` | 缺少有效汇率等失败，可重试 |

身份是稳定规则 UUID + 月份，不是金额或更新时间。`FAILED` 重试沿用原策略版本，其他状态不由自动检查重建。实际、月度容器与发生槽的形成由事务保护；编辑实际不重置身份，删除实际在同一事务消费发生槽。外币使用已保存汇率，普通汇率需有效观察日期，不能把缺失日期静默当作今天。

## 跨月专项

专项保存本位币总预算、归档状态和备注；月分配限定三类支出，同专项、月份、类别唯一。应用事务保证分配合计不超过总预算，已形成月度快照的分配不可改写或删除。

专项采用 `SPECIAL_PROJECT` 月度容器，`AMORTIZED` 仅作无支付日标记，金额直接取分配，不执行周期均摊公式。无分配实际可创建零计划容器。实际条目只有一份，项目归属由父月度项目派生。

```text
未分配预算 = 总预算 - 月分配合计
净剩余预算 = 总预算 - 实际净支出
```

实际超支可以保存；跨月退款落在退款发生月。归档保留预算与事实，仍允许补录晚到实际，不自动摊分预算池或滚动结余。

## 借贷、本金与费用

借贷是独立聚合。`BORROWED` 为借入，`LENT` 为借出；首期只支持本位币。完整记录模式把初始本金记入发生日现金流，期初余额模式只建立跟踪起点。追加借入/借出按实际日期增加本金和现金流。

```text
剩余本金 = 初始本金 + 追加本金合计 - 实际归还本金合计
```

分期支持日、月、季度、年及正整数间隔，等额本金、等额本息或手动逐期计划。月/季/年使用首次日期原始日锚点，利率明确为每期利率，不猜测年化或日计息惯例。

每笔还款/回款保存本金、利息、费用与期次分配。稳定请求 UUID 防止重复写入，编辑/删除使用更新时间检查。预览在回滚事务中计算分配，不改动已存事实。重排保留历史和已付款关联，替代允许调整的后续期次。

可选计息规则独立于分期计划。领域函数 `accrue_loan_interest` 按实际本金变动和已付利息推算单利、周期复利或固定额利息，支持日/月/季/年。区间为起息日至截至日的左闭右开区间，周期锚定起息日，不足周期按实际天数折算；先累计同周期的本金日贡献再除以周期天数，最终舍入到分。复利在完整周期边界结转未付利息，已付超额保留抵扣。估算不写月度实际、不叠加到分期预算；只有保存实际收付才沿原关联链记账。规则更新与资料变更同事务，归档更新省略规则时保留原设置。

本金仅进入余额与现金流。利息和费用通过每合同、月份唯一的月度容器及一对一实际关联进入收支；保存/编辑/删除收付、期次分配和关联实际均由同一事务维护，避免双记。本金约束检查每个发生日结束余额，未来追加不能支撑更早的还款。追加纠错也不能造成历史负本金。

剩余本金与有效未还分期不一致时标记需核对计划；状态、余额、逾期与结清由事实派生，不另存手工状态。

## 分析与前端缓存

月度分析由 [`analytics.rs`](../src-tauri/src/application/analytics.rs) 从快照与净实际生成，历史接口逐月复用同一口径。月报、年报、排名、偏差及趋势均不持久化，不需要“重新生成报表”。

- 收入/支出方向无条目时保持空值；只在已有任意实际的月度净结余运算中，将缺少一侧视为零。
- 项目偏差仅在有计划基准和实际时计算；正负含义取决于收入或支出方向。计划额为零时不计算完成率。
- 月度储蓄率在收入非零时计算，年度汇总当前在收入大于零时计算；其他零分母比例返回空值。
- 年度只汇总已有月度 DTO，未录月份保持缺失；饼图以可绘制的正额展示，占比数据仍在表格保留。

历史“调整该月数据”和“调整条目”以月份/项目 UUID 打开同一月度工作台，复用实际 CRUD。查询键区分月度项目、实际、预览、分析、月份列表、专项、借贷和下月投影。财务写入后统一失效相关查询，入口见 [`refreshFinancialQueries.ts`](../src/features/automatic/refreshFinancialQueries.ts)。

## 存储、IPC 与安全

启动解析应用数据目录并打开 `aplena.sqlite3`，使用外键、WAL、`synchronous=NORMAL`、5 秒 busy timeout 及最多 5 条连接。Unix 下目录设为 `0700`，数据库及已有 WAL/SHM 设为 `0600`。检查成功迁移版本后执行嵌入迁移；未来版本、校验和不匹配或迁移失败会阻止进入业务流程。

数据库未静态加密。权限和操作系统账户是当前保护边界，SQLCipher/系统凭据集成为未来候选。[开发文档](development.md)说明隔离冒烟目录与受控旧库转换，不能拿真实用户库测试。

IPC 实际注册表在 [`lib.rs`](../src-tauri/src/lib.rs)，DTO 与错误协议在 [`application`](../src-tauri/src/application)。命令覆盖规则、月度实际、专项、自动入账、借贷、分析及独立软件更新；错误返回稳定 `error_code`、可空 `field`、`message_key` 和安全参数，不向 UI 传递 SQL、路径或原始堆栈。

[`capabilities/main.json`](../src-tauri/capabilities/main.json) 只开放最小窗口能力，不向 WebView 开放 updater、shell 或任意文件系统插件权限。CSP 允许前端读取 ECB 汇率，软件更新网络请求由 Rust 执行；财务数据不上传。

更新服务使用独立互斥状态机，阶段包括检查、可更新、下载、验签、安装、等待重启；通过 `software-update://status` 事件发送进度。它只接受受限 HTTPS GitHub Releases 端点及比当前版本新的稳定 SemVer。插件负责下载和 minisign 验签，仓库内 macOS 安装器在同卷验证应用身份并以 `RENAME_SWAP` 交换；不采用双重 rename、AppleScript 或提权回退。签名与发行检查见[开发、构建与发行](development.md)。
