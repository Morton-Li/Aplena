## 维护约定

- 功能行为写在产品文档，公式与事务边界写在架构文档，列和迁移写在数据库文档，避免多处维护同一份说明。
- 文档随实现更新；未实现能力明确标为候选，不以旧路线图代替当前状态。
- 当前代码、配置、迁移与工作流是事实依据；文档给出对应源码入口。
- 测试数量、机器产物路径和某次发布结论属于当次验证记录，不作为长期就绪证明。发行时按开发文档重新取得对应提交的证据。
- 已完成的阶段路线和一次性核对材料从现行目录移除，完整历史保留在 Git 中。
