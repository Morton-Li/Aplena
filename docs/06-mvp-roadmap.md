# Aplena MVP 路线与状态

## 1. 当前定义

当前 MVP 已从“电子表格月度总额替代品”升级为“计划关联的项目级实际条目系统”。它仍然不是逐笔银行卡记账：条目只能进入已有长期计划对应的月度项目，用户维护的是项目结果而非完整消费流水。

完成标准同时包括产品能力、数据兼容、测试、发布构建和隔离真实应用冒烟；单纯前端可见不视为完成。

## 2. 已完成能力

### 阶段 1：领域与本地架构

- Tauri 2、Rust、React、TypeScript、SQLite；
- 五类财务项目及收入/支出派生；
- 本位币、汇率、储蓄目标；
- 两种计入模式和财务承载能力；
- 本地优先、最小权限与稳定 IPC 错误。

### 阶段 2：计划与月度快照

- 长期计划新建、编辑、停止、删除；
- 当前自然月自动初始化；
- 未来和历史月份只读预览及显式初始化；
- 临时历史汇率覆盖；
- 并发幂等、全事务回滚和快照不可变；
- PAYMENT 支付日快照。

### 阶段 3：Dashboard、历史与分析

- 收入、支出、结余、储蓄率；
- 类别结构、项目占比、排名和重要偏差；
- 历史趋势和完整度；
- 收入/支出的有利、不利偏差语义；
- 承载能力月均等价口径。

### 阶段 4：数据保护

- WAL 一致性完整备份；
- manifest、SHA-256、大小和表摘要；
- 检查后一次性 token 恢复；
- 路径、符号链接、重复项、压缩炸弹、记录数保护；
- 迁移前和恢复前恢复点；
- 确定性 CSV 与公式注入防护。

### 阶段 5：日级日期、分精度和实际条目

- 金额权威精度统一为两位；
- 计划开始/结束日期精确到日；
- AMORTIZED 按月区间交集、无按日比例；
- PAYMENT 原始日锚点、短月夹取、长月恢复；
- 项目关联 `ActualEntry` 增删改查；
- 支出/退款、收入/冲减，净额允许为负；
- 四种完整状态和确认重开；
- 无计划快照月份的 `ACTUAL_ONLY`；
- 仅实际快照到正式快照的事务内原位提升；
- schema 3 前向迁移和格式 1 旧备份兼容；
- 格式 2 五表备份与五份 CSV。

## 3. 本阶段发布验收

### 3.1 领域与数据库

- 两位金额拒绝第三位小数且覆盖范围溢出；
- 闰年、月首/月末交集和精确结束日有测试；
- 1 月 31 日锚点覆盖平年、闰年和恢复到 3 月 31 日；
- schema 2 旧库的金额、日期、空/零/正实际迁移有回归；
- 旧实际不会继续以持久化聚合总额存在；
- 五表、外键、触发器、索引和不变量检查通过。

### 3.2 实际条目与分析

- 新增、编辑、删除、同月日期、正金额、禁止改挂有测试；
- 退款超过支出或冲减超过收入时净额可以为负；
- 条目 CRUD 自动取消确认；
- 确认零不创建虚假条目；
- 已结束计划允许迟到事实，已删除计划拒绝新条目；
- 仅实际原位提升保留 ID、条目和确认，且重复执行幂等；
- 月度、历史、类别、项目和偏差均从条目实时派生。

### 3.3 前端

- 计划表单使用日级日期和两位金额；
- 月度净实际不可直接编辑；
- 全局与上下文两级条目录入可用；
- 退款/冲减文案随方向变化；
- 四种状态、仅实际、计划支付日和迁移条目只读可见；
- 变更后相关查询自动刷新；
- 键盘、可访问标签、窄窗口布局和错误文案通过检查。

### 3.4 数据保护

- 格式 2 备份五表完整往返；
- 格式 1 旧备份在隔离副本升级、检查并恢复；
- CSV 五文件、两位金额、派生实际标识、NULL/0 和公式防护；
- 恢复失败不改变当前库；
- 从不使用真实用户数据库进行测试。

### 3.5 工程发布门

必须通过：

```text
pnpm typecheck
pnpm lint
pnpm test
pnpm build
cargo fmt --all -- --check
cargo check --workspace --offline
cargo test --workspace --offline
cargo clippy --workspace --all-targets --offline -- -D warnings
pnpm tauri build --bundles app
```

随后以系统临时目录下的隔离 `APLENA_SMOKE_DATA_DIR` 启动 release `.app`，验证首次设置、日级计划、自动初始化、实际条目、退款、确认、分析刷新、重启持久化和应用退出。

## 4. Git 交付门

本阶段在 `feature/actual-entries-daily-dates-cents` 实现。门禁和冒烟通过后：

1. 功能分支提交；
2. 显式合并到 `develop`；
3. 验证合并结果；
4. 显式合并到 `main`；
5. `main` 工作树干净。

本阶段不推送、不打标签、不创建线上发布。

## 5. MVP 后候选

按价值排序：

1. Scenario 沙盒：不改正式计划模拟收入下降或支出变化；
2. 3/6 个月移动平均与环比；
3. 可选的端到端数据库加密；
4. 用户明确要求时再评估外部同步或交易导入。

下列内容不应未经验证进入模型：自由流水、复式记账、预算公式字段、派生报表持久化和自动重算历史快照。

## 6. 变更控制

涉及以下任一项必须新增 ADR 或更新现有 ADR：

- 金额精度、舍入或日期计入；
- 历史快照与实际条目权威来源；
- 月度自动写入边界；
- 数据库实体、备份格式或恢复流程；
- 加密、同步、远程服务或权限扩张。
