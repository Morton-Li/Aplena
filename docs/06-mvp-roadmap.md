# Aplena MVP 路线与状态

## 1. 当前定义

当前 MVP 是“月度项目级实际条目系统”，并以周期规则提供可选的自动化与下月预算投影。它仍然不是逐笔银行卡记账：条目进入分类明确的月度项目，用户维护的是项目结果而非完整消费流水；周期规则不再是强制前置条件。

完成标准同时包括产品能力、数据兼容、测试、发布构建和隔离真实应用冒烟；单纯前端可见不视为完成。

## 2. 已完成能力

### 阶段 1：领域与本地架构

- Tauri 2、Rust、React、TypeScript、SQLite；
- 五类财务项目及收入/支出派生；
- 本位币与汇率；
- 两种计入模式和规则驱动的下月预算投影；
- 本地优先、最小权限与稳定 IPC 错误。

### 阶段 2：计划与月度快照

- 长期计划新建、编辑结束日期、删除；
- 当前自然月仅在启动时自动初始化，规则保存不回填本月；
- 未来和历史月份只读预览及显式初始化；
- 临时历史汇率覆盖；
- 并发幂等、全事务回滚和快照不可变；
- PAYMENT 支付日快照。

### 阶段 3：Dashboard、历史与分析

- 收入、支出、结余、储蓄率；
- 类别结构、项目占比、排名和重要偏差；
- 历史趋势和类目数据基准；
- 收入/支出的有利、不利偏差语义；
- 下月预算投影的月均等价口径。

### 阶段 4：日级日期、分精度和实际条目

- 金额权威精度统一为两位；
- 计划开始/结束日期精确到日；
- AMORTIZED 按月区间交集、无按日比例；
- PAYMENT 原始日锚点、短月夹取、长月恢复；
- 项目关联 `ActualEntry` 增删改查；
- 支出/退款、收入/冲减，净额允许为负；
- 不设计类目确认或完成状态；
- 无计划快照月份的 `ACTUAL_ONLY`；
- 无长期计划时可独立创建、删除 `MANUAL` 临时类目并录入实际；
- 仅实际快照到正式快照的事务内原位提升；
- 预发布阶段用 `item_origin` 扩展月度项目；正式 schema 1 已直接包含该字段与约束。

### 阶段 5：下月预算投影

- “配置预算”页集中展示规则派生的预计收入、支出、储蓄、储蓄率和支出类型占比，并维护可选周期规则；
- 目标月份由后端固定为下一个自然月，客户端不能选择当前或历史月；
- 当前月和历史分析只比较各月冻结计划与实际，下月投影不混入历史口径；
- schema 3 删除 `next_month_goal` 表与旧目标数据，不保留兼容读取；
- 预计储蓄保留负缺口，支出饼图不混合收入，精确数据采用固定高度翻转；
- 保存周期规则不再自动初始化当前月。

## 3. 本阶段发布验收

### 3.1 领域与数据库

- 两位金额拒绝第三位小数且覆盖范围溢出；
- 闰年、月首/月末交集和精确结束日有测试；
- 1 月 31 日锚点覆盖平年、闰年和恢复到 3 月 31 日；
- 新库按顺序建立 schema 1 并迁移到 schema 4；冻结的预发布最终结构应用 schema 2 至 schema 4 后与当前结构等价；
- 旧实际不会继续以持久化聚合总额存在；
- 五张当前业务表、外键、触发器、索引和不变量检查通过。

### 3.2 实际条目与分析

- 新增、编辑、删除、同月日期、正金额、禁止改挂有测试；
- 退款超过支出或冲减超过收入时净额可以为负；
- 没有条目时实际保持为空，不创建虚假零金额条目；
- 已结束计划允许迟到事实，已删除计划拒绝新条目；
- 手动月度项目无需计划即可新增条目，且不制造计划偏差；
- 仅实际原位提升保留 ID 和条目，且重复执行幂等；
- 月度、历史、类别、项目和偏差均从条目实时派生。

### 3.3 前端

- 计划表单使用日级日期和两位金额；
- 月度净实际不可直接编辑；
- 全局入口创建临时类目，上下文入口维护实际条目；
- 退款/冲减文案随方向变化；
- 临时类目、计划外预算类目、计划支付日和迁移条目只读边界可见；
- 新建条目日期默认当日，编辑/创建模态打开时详情抽屉保持挂载；
- 条目删除确认位于抽屉上层，临时类目删除要求显式二次确认；
- 变更后相关查询自动刷新；
- “配置预算”页将下月概览与支出饼图同排，规则变更只刷新下月投影；
- 总览缺失图表值显示为 0，精确数据翻转不会拉伸相邻卡片；
- 键盘、可访问标签、窄窗口布局和错误文案通过检查。

### 3.4 工程发布门

必须通过：

```text
pnpm typecheck
pnpm lint
pnpm test
pnpm build
cargo fmt --all -- --check
cargo check --workspace --offline
cargo test --workspace --offline
cargo clippy --workspace --all-targets --offline -- -D warnings
pnpm tauri build --bundles app
```

随后以系统临时目录下的隔离 `APLENA_SMOKE_DATA_DIR` 启动 release `.app`，验证默认设置直达应用、临时类目创建/删除、实际录入与退款、抽屉和上层对话框、可选计划初始化、分析刷新、重启持久化和应用退出。

## 4. Git 交付门

本阶段在 `feature/actual-entries-daily-dates-cents` 实现。门禁和冒烟通过后：

1. 功能分支提交；
2. 显式合并到 `develop`；
3. 验证合并结果；
4. 显式合并到 `main`；
5. `main` 工作树干净。

本阶段不推送、不打标签、不创建线上发布。

## 5. MVP 后候选

按价值排序：

1. Scenario 沙盒：不改正式计划模拟收入下降或支出变化；
2. 3/6 个月移动平均与环比；
3. 可选的端到端数据库加密；
4. 用户明确要求时再评估外部同步或交易导入。

下列内容不应未经验证进入模型：自由流水、复式记账、预算公式字段、派生报表持久化和自动重算历史快照。

## 6. 变更控制

涉及以下任一项必须新增 ADR 或更新现有 ADR：

- 金额精度、舍入或日期计入；
- 历史快照与实际条目权威来源；
- 月度自动写入边界；
- 数据库实体或迁移流程；
- 加密、同步、远程服务或权限扩张。
