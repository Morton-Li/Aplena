# 预发布本地数据库换轨方案

状态：仅方案，尚未执行

适用范围：把首个正式版之前的本地测试数据换轨到 `0001_initial_release.sql`。这不是面向最终用户的导入、备份、恢复或导出功能，也不会进入正式运行时。

## 1. 当前风险与保护

预发布数据库记录了旧迁移版本和校验和，正式版则从 schema 1 建立新的公开兼容边界。直接让新程序打开旧库可能遇到“数据库 schema 更新”或迁移校验和不一致；不得通过改写 `_sqlx_migrations`、删除旧库或静默重建来绕过。

当前正式版在运行迁移前检查已应用版本。最终预发布库通常记录版本 6，高于正式基线版本 1，因此会安全拒绝并关闭连接。自动测试证明该拒绝不会修改旧库内容。真实数据库在用户明确授权换轨前保持原状。

## 2. 可恢复副本

执行换轨前必须：

1. 正常退出所有 Aplena 进程，并确认没有持有数据库连接；
2. 记录旧应用构建和旧数据库目录位置，不启动新应用读取该目录；
3. 对整个旧数据目录建立只读、带时间戳的副本，同时保留主数据库及可能存在的 `-wal`、`-shm` 文件；
4. 对副本计算文件大小与 SHA-256，并把副本再复制一份作为只读恢复点；
5. 所有检查先在工作副本进行，原目录和只读恢复点不参与写入。

若旧进程无法正常退出或副本中的 SQLite 检查失败，应停止换轨，不尝试修复原库。

## 3. 新旧结构与数据复制

1. 在系统临时目录创建全新的空数据目录；
2. 用目标正式版启动一次并正常退出，让 SQLx 顺序执行 schema 1 至 schema 4；
3. 确认新库 `_sqlx_migrations` 有成功的版本 1 至 4，五张当前业务表均为空，且不存在 `next_month_goal`；
4. 在独立工具进程中以只读方式附加旧库工作副本，以读写方式打开新库；
5. 先比较旧库最终结构与冻结夹具，确认它确实是受支持的预发布最终结构；
6. 在单一事务中按以下顺序使用显式字段列表复制，不复制 `_sqlx_migrations`；复制 `settings` 时不写入新增的 `auto_update_exchange_rates`，使用默认关闭；复制 `monthly_items` 时不包含旧 `actual_confirmed_at`：
   `exchange_rates` → `settings` → `plan_items` → `monthly_items` → `actual_entries`；
7. 提交前启用外键，并在任何插入、约束或核对失败时整体回滚。

除被 schema 2 明确删除的类目确认字段、3 个重开触发器，被 schema 3 明确删除的下月目标表，以及 schema 4 新增且默认关闭的启动汇率更新偏好外，新旧业务结构由自动测试证明等价，因此正常情况下不需要金额换算、日期转换或重写 UUID。旧确认时间和旧储蓄目标不进入新库，这是已确认的数据舍弃。若旧库不是最终预发布 schema，则停止并单独评估，不能临时把兼容逻辑加入正式运行时。

## 4. 必须通过的核对

在替换任何路径前，对新库和旧库工作副本分别执行并保存结果：

- `PRAGMA integrity_check` 必须为 `ok`；
- `PRAGMA foreign_key_check` 必须无行；
- 五张当前业务表逐表 `COUNT(*)` 相等；
- 设置与本位币逐字段相等，并确认新库不存在旧目标表；
- 计划金额、月度计划金额、实际条目源金额和本位币金额的总和相等；
- `INCREASE - DECREASE` 的全局净额、逐月净额、逐类别净额相等；
- UUID、月度项目来源、外币代码、汇率快照来源和观察日期相等；旧确认时间不复制；
- 新库只有正式 migration 版本 1 至 4，旧库的 migration 历史没有被复制；
- 用隔离数据目录启动目标 `.app`，检查总览、月度执行、历史报表和配置预算后正常退出；
- 重启同一隔离目录，确认数据持久化且上述 SQLite 检查仍通过。

金额核对必须使用整数列，不使用 `REAL` 或格式化后的界面字符串。除总和外还要核对最小值、最大值以及按月份分组的行数，防止正负抵消掩盖遗漏。

## 5. 切换与失败回退

只有全部核对通过并再次获得用户确认后，才能把验证过的新目录切换为正式数据目录。切换采用同一文件系统内的可恢复目录重命名，旧目录先改为带时间戳的保留名，新目录再进入目标位置；不得覆盖只读恢复点。

任一步失败时：

1. 停止目标应用；
2. 丢弃失败的新库副本，不改动原库和只读恢复点；
3. 恢复旧目录名并使用对应的预发布应用版本；
4. 保存失败步骤、SQLite 错误和核对差异，重新制定方案；
5. 未定位原因前不重复执行，也不修改迁移历史伪造成功状态。

本方案当前没有执行，真实用户数据库、`_sqlx_migrations` 和应用支持目录均未被读取或更改。
