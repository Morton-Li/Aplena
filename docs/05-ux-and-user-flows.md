# Aplena UX 与用户流程

## 1. 体验原则

1. 用户维护分类明确的月度项目结果；长期计划是可选增强，不是前置条件；
2. 计划金额与实际净额在月度卡片上并列但均只读；
3. 实际通过少量、有项目上下文的条目构成；
4. 新月份自动进入，浏览历史和未来不会意外写入；
5. 收入与支出使用符合语义的文案，而不是要求用户理解正负号；
6. 日级日期和两位金额在输入处即时受限；
7. 历史与汇率操作明确说明数据口径和不可逆语义。

## 2. 信息架构

侧栏页面：

- Dashboard；
- 月度执行；
- 历史报表；
- 配置预算；
- 设置。

总览和月度执行固定为当前自然月，历史报表按已存在月份浏览。“配置预算”固定为下一个自然月；三者互不改写。

## 3. 首次启动

应用不显示启动向导。首次启动直接创建人民币（CNY）、当前自然月快照上下文和默认下月储蓄目标并进入总览。本位币在设置修改，下月储蓄率在“配置预算”修改。已有月度数据后本位币锁定。

## 4. 目标与周期规则流程（可选增强）

页面首屏必须明确显示“当前月不联动、历史月不回溯、仅下月生效”。不设置目标或周期规则也可录入月度实际并查看基础报表；周期规则用于周期自动化、偏差基准和下月承载能力。

### 4.1 表单

字段包括名称、类别、金额、币种、周期、模式、开始日期、结束日期和备注。

- 金额输入只接受非负且最多两位小数；
- 日期使用原生日控件；
- 开始日期必填，新规则默认下一个自然月第一日；
- 结束日期可空且不得早于开始日期；
- 收支方向随类别展示为只读；
- 周期是正整数月数。

### 4.2 模式选择

选项卡文案：

| 模式 | 解释 |
|---|---|
| 按月均摊 | 有效期与月份相交时，每月计入完整月均负担，不按天数比例 |
| 按支付月份确认 | 以开始日期为原始支付日锚点，每隔周期月计入完整金额 |

PAYMENT 需说明短月夹到月末但随后恢复原锚点，并在预览里展示目标月计划支付日期。

### 4.3 预览再保存

前端把原始表单交给后端预览，展示：是否在目标月有效、是否计入、计划支付日、月均等价、本月计划额和本位币。前端不自行执行汇率或周期公式。

### 4.4 停止和删除

停止要求选择精确结束日期。删除对有历史的计划明确提示：长期计划会删除，但既有快照和实际条目保留并与来源脱离。已脱离的快照不能继续添加条目。

## 5. 月份生命周期

### 5.1 当前自然月

应用启动后自动检查当前月。目标或周期规则保存不会触发当前月写入；月度执行中的显式补齐保持幂等且不覆盖任何快照或实际条目。

### 5.2 未来月份

选择未来月份先显示只读预览。只有点击“确认并初始化未来月份”、阅读快照冻结说明并勾选确认后才写入。

### 5.3 历史月份

已有快照直接查看。缺失历史月份必须走“补录这个历史月份”，界面警告当前汇率可能不代表历史；可为本次操作输入临时汇率。临时值不保存。

### 5.4 PAYMENT 空月份

若没有应支付项目，页面可以为空，这是正确状态，不生成零计划快照。用户仍可通过“添加实际条目”直接建立本月项目，或为现有计划记录迟到退款、冲减或意外实际。

## 6. 月度计划页面

### 6.1 月度卡片

每个卡片显示：

- 项目名、类别、方向、计入模式；
- 手动项目显示“本月项目”，关联计划但无正式快照时显示“计划外实际”；
- PAYMENT 的计划支付日期；
- 只读计划金额、条目派生实际净额、偏差和完成率；
- 完整状态和条目数；
- 添加条目、展开条目、最终确认和月度备注操作。

空实际显示“尚无条目”，确认零显示 `0.00`，不能用输入框 placeholder 混淆两者。

### 6.2 两级实际录入

上下文入口按钮：

- 支出项目：“添加支出或退款”；
- 收入项目：“添加收入或冲减”。

项目固定，用户填写日期、类型、正金额和可选备注。

全局入口“添加实际条目”默认选择“本月项目”，填写项目名称、类别、日期、类型和金额，不需要长期计划。若用户切换到“关联长期计划”，再选择计划；目标月没有对应月度项目时自动创建 `PLAN_LINKED + ACTUAL_ONLY`，再写条目。选择已结束计划时显示迟到事实提示，但允许继续。

日期控件的最小值和最大值限制在所选月，后端仍会再次验证。金额必须大于 0 且最多两位；退款和冲减通过类型选择，不输入负数。

### 6.3 条目列表

展开后按日期显示金额效果、备注和来源：

- 用户条目可编辑和删除；
- 删除二次确认，并说明项目会重新待确认；
- 迁移聚合条目显示迁移说明且没有编辑/删除按钮。

条目保存后自动刷新卡片、Dashboard、历史与分析。

## 7. 确认状态

界面文案：

| 代码 | 用户文案 | 含义 |
|---|---|---|
| `MISSING` | 尚未开始 | 无条目且未最终确认 |
| `IN_PROGRESS` | 记录中 | 有条目但未最终确认 |
| `CONFIRMED_ZERO` | 已确认零 | 无条目，确认本月没有实际 |
| `FINAL` | 最终确认 | 条目已核对完成 |

“确认项目已完成”和“确认所选范围已完成”只写确认标记。界面必须明确不会以计划值补实际。条目后续发生任何改变，状态自动回到记录中或尚未开始。

## 8. Dashboard 与分析

### 8.1 总览

显示实际收入、支出、结余、储蓄率和完整度。有计划基准时增加计划对比。实际为空时不能伪装成零；部分完成时用明确状态提示。

### 8.2 偏差文案

- 收入：实际高于计划为有利，低于计划为不利；
- 支出：实际低于计划为有利，高于计划为不利；
- `PLAN_LINKED + ACTUAL_ONLY` 保留计划外事实语义；
- `MANUAL` 项目进入实际汇总与排名，但没有计划基准，因此不生成偏差。

颜色只是辅助，徽标和文字必须表达含义。

### 8.3 储蓄率

当前月和历史月只标注“相差 X 个百分点”和“计划完成率 X%”，均基于该月冻结计划。下月储蓄目标只在“配置预算”页显示。

收入为零时显示 `N/A` 并说明分母不足。

### 8.4 图表

至少提供收入、支出、结余和储蓄率历史趋势；项目较多时优先排序横条图。图表旁保留数值表或可访问文本，不能只靠图形。

## 9. 财务承载能力

该区域只出现在“配置预算”页，是周期规则启用后的下月增强分析。没有周期规则时显示“可选增强项”，不展示 `0.00` 结果。启用后展示保守可用空间和最大可用空间，并解释：

```text
保守空间 = 固定收入 - 必要支出 - 固定承诺 - 自主预算 - 储蓄目标
最大空间 = 固定收入 + 浮动收入 - 必要支出 - 固定承诺 - 自主预算
```

PAYMENT 项按月均等价计入。负值不截断为零，以暴露结构性缺口。固定承诺占比和稳定收入覆盖倍数作为辅助指标。

## 10. 设置

设置页只包含本位币与汇率。已有月度数据后本位币保持锁定；汇率变更只影响后续新建快照。储蓄目标不得重复出现在设置页。

## 11. 错误与可访问性

- 每个输入错误靠近对应字段；
- 业务错误使用可理解文案，未知错误不泄露 SQL、路径或堆栈；
- 对话框有标题、关闭按钮、键盘焦点顺序和清晰主操作；
- 所有输入都有可访问标签；
- 状态不用颜色单独表达；
- 表格、图表和按钮在窄窗口可重排；
- 尊重减少动画系统设置。

## 12. 关键验收旅程

1. 首次启动直接进入总览 -> 月度执行创建“本月工资” -> 总览生成实际报表；
2. 创建 1 月 31 日 PAYMENT 计划 -> 预览 2 月末与 3 月 31 日支付日；
3. 在支出项目添加支出与退款 -> 净额、偏差和分析自动变化；
4. 不设置长期计划直接添加本月支出 -> 建立手动月度项目 -> 实际汇总不制造计划偏差；
5. 在无计划快照月份关联计划添加退款 -> 建立“计划外实际”项目 -> 后续初始化原位提升且条目不丢；
6. 确认零 -> 新增条目 -> 自动回到记录中；
7. 删除有历史的计划 -> 历史仍可查看但不能新增条目。
8. 在“配置预算”保存储蓄率或周期规则 -> 下月承载力刷新 -> 当前月和历史月报表不变化。
