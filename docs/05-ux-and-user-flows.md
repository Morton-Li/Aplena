# Aplena UX 与用户流程

## 1. 体验原则

1. 用户维护分类明确的月度项目结果；长期计划是可选增强，不是前置条件；
2. 计划金额与实际净额在月度卡片上并列但均只读；
3. 实际通过少量、有项目上下文的条目构成；
4. 新月份自动进入，浏览历史和未来不会意外写入；
5. 收入与支出使用符合语义的文案，而不是要求用户理解正负号；
6. 日级日期和两位金额在输入处即时受限；
7. 历史与汇率操作明确说明数据口径和不可逆语义。

## 2. 信息架构

侧栏页面：

- Dashboard；
- 月度执行；
- 专项；
- 历史报表；
- 配置预算；
- 设置。

总览固定为当前自然月；主导航进入的月度执行同样默认当前月。历史报表按已存在月份浏览，并可通过明确的“调整该月数据”或“调整条目”入口把月度执行工作台切换到所选历史月。“配置预算”固定为下一个自然月。浏览本身不写数据，只有明确的保存、删除或初始化操作才会修改对应月份。

## 3. 首次启动

应用不显示启动向导。首次启动直接创建人民币（CNY）与当前自然月快照上下文并进入总览。本位币在设置修改；“配置预算”根据周期规则和专项下月分配只读派生结果。已有月度数据或专项预算后本位币锁定。

## 4. 下月预算与周期规则流程（可选增强）

页面首屏明确显示系统计算的下一个自然月。不设置周期规则也可录入月度实际并查看基础报表；周期规则用于周期自动化、偏差基准和下月预算投影，规则变更不会回写当前月或历史月。

### 4.1 表单

字段包括名称、类别、金额、币种、周期、模式、开始日期、结束日期和备注。

- 金额输入只接受非负且最多两位小数；
- 日期使用原生日控件；
- 开始日期必填，新规则默认下一个自然月第一日；
- 结束日期可空且不得早于开始日期；
- 收支方向随类别展示为只读；
- 周期是正整数月数。

### 4.2 模式选择

选项卡文案：

| 模式 | 解释 |
|---|---|
| 按月均摊 | 有效期与月份相交时，每月计入完整月均负担，不按天数比例 |
| 按支付月份确认 | 以开始日期为原始支付日锚点，每隔周期月计入完整金额 |

PAYMENT 需说明短月夹到月末但随后恢复原锚点，并在预览里展示目标月计划支付日期。

### 4.3 预览再保存

前端把原始表单交给后端预览，展示：是否在目标月有效、是否计入、计划支付日、月均等价、本月计划额和本位币。前端不自行执行汇率或周期公式。

### 4.4 编辑结束日期和删除

周期规则行只提供编辑和删除操作。需要停止后续月份时，通过编辑设置精确结束日期。删除对有历史的计划明确提示：长期计划会删除，但既有快照和实际条目保留并与来源脱离。已脱离的快照不能继续添加条目。

### 4.5 下月概览与支出类型占比

配置预算页把“下月预算概览”和“支出类型占比”放在同一行，窄窗口改为上下排列。概览展示预计收入、预计支出、预计储蓄和预计储蓄率；支出饼图只使用必要支出、固定承诺支出和自主性预算的本位币月度等价金额，不能直接累加不同币种原始金额，也不能把收入混入同一占比分母。金额为零的类型不生成扇区；没有可计入金额时显示空状态。

图表使用固定高度正反面：正面为图形，背面为精确数据表，按钮在两面间切换。翻转中点附近以前一面淡出、后一面延迟淡入衔接，不能通过突然切换可见性制造闪烁。背面内容过多时只在卡片内部滚动，不能拉伸同一网格行；隐藏面不可聚焦，并尊重减少动态效果系统设置。

### 4.6 自动入账开关

新规则默认关闭自动入账。开启时显示首次支付日期、完整单次金额、原周期与下月生效说明；多月均摊规则必须明确首次支付日。保存规则成功而策略保存失败时，要说明已经保存的部分并允许重试。关闭立即停止未执行记录，已经形成的实际仍可编辑或删除。

月度执行显示自动入账摘要和检查按钮。到期记录直接成为正式实际并显示自动徽标；发现已有手动条目时提供关联所选记录、跳过本次、明确另建一笔三个动作。失败显示可理解原因，修复汇率后可重试。删除自动记录的确认应说明以后检查也不会重建。

## 5. 月份生命周期

### 5.1 当前自然月

应用启动后自动检查当前月。周期规则保存不会触发当前月写入；月度执行中的显式补齐保持幂等且不覆盖任何快照或实际条目。

### 5.2 未来月份

选择未来月份先显示只读预览。只有点击“确认并初始化未来月份”、阅读快照冻结说明并勾选确认后才写入。

### 5.3 历史月份

已有快照直接查看。月度详细报告提供整月调整入口，项目对照表提供项目级调整入口；进入后可补录、编辑或删除用户实际条目，也可维护该月临时类目和月度备注。报告和计划快照本身仍为派生/冻结数据，不直接改写。缺失历史月份必须走“补录这个历史月份”，界面警告当前汇率可能不代表历史；可为本次操作输入临时汇率。临时值不保存。

### 5.4 PAYMENT 空月份

若没有应支付项目，页面可以为空，这是正确状态，不生成零计划快照。用户仍可通过“添加临时类目”建立本月的非预算类目，再从详情抽屉记录实际。

## 6. 月度计划页面

### 6.1 月度类目表格

每个卡片显示：

- 项目名、类别、方向、计入模式；
- 手动项目显示“临时类目”，关联计划但无正式快照时显示“计划外预算类目”；
- PAYMENT 的计划支付日期；
- 只读计划金额、条目派生实际净额、偏差和完成率；
- 实际条目数；
- 查看详情、添加条目和月度备注操作。

空实际显示“—”；只有实际条目净额为零时才显示 `0.00`。表格没有类目状态列，详情也没有“确认项目已完成”操作。

### 6.2 临时类目与实际录入

上下文入口按钮：

- 支出项目：“添加支出或退款”；
- 收入项目：“添加收入或冲减”。

类目固定，用户填写日期、类型、正金额和可选备注。新建支出、退款、收入或冲减时，日期默认为当日；若当前执行月不是当日所在月，则回退到该月第一日。编辑保留原日期。

全局入口为“添加临时类目”，只填写类目名称、财务类别和可选备注，不同时创建实际条目。创建完成后打开该类目的详情抽屉，再通过上下文入口添加实际。

日期控件的最小值和最大值限制在所选月，后端仍会再次验证。原币金额支持直接输入金额，或使用 `+`、`-`、`*`、`/` 和括号组成运算式，各数值项最多两位小数；按标准优先级进行精确十进制运算，只在最终结果处 `ROUND_HALF_UP` 到分，保存值只包含固定两位结果，不包含原运算式。结果必须大于 0；退款和冲减通过类型选择，不输入负数。保存按钮除提交过程中外保持可操作；金额为空、运算式不合法、除数为零或结果无效时，点击保存应在金额字段旁明确说明规则，不能以无提示禁用代替校验反馈。

录入币种为本位币时不显示“本次换算基准”。录入外币时，换算基准至少显示两位小数；超过两位的部分只保留到最后一个非零位，不展示无意义的末尾零。保存仍使用完整的八位汇率快照，显示格式不改变计算精度。

### 6.3 条目列表

展开后按日期显示金额效果、备注和来源：

- 用户条目可编辑和删除；
- 删除使用位于抽屉上层的应用内二次确认，取消、Escape 和确认都必须可操作；
- 迁移聚合条目显示迁移说明且没有编辑/删除按钮。

创建或编辑条目时详情抽屉保持挂载，不因上层模态对话框打开而消失。条目保存后自动刷新类目、Dashboard、历史与分析。

## 7. 类目状态与删除边界

月度类目没有 `MISSING`、`IN_PROGRESS`、`CONFIRMED_ZERO` 或 `FINAL` 等生命周期状态，也没有单项或批量完成确认。没有实际条目表示实际未知/尚不存在，不自动等价为零。

只有用户创建的临时类目显示“删除临时类目”。确认对话框必须说明实际条目数量和不可撤销性；确认后类目与其实际条目在同一事务中删除。预算类目、计划外预算类目和周期规则不受影响，也不提供同类删除入口。

## 8. Dashboard 与分析

### 8.1 总览

显示实际收入、支出、结余和储蓄率。有计划基准时增加计划对比；报表展示类目数量和数据基准，不推导核对进度。实际为空时，指标和精确报表仍使用“—”表达未知；柱状图只为避免未定义提示而把缺失指标绘制在 `0` 轴。历史折线图只把已经结束月份的缺失点补为 `0`，当前月和未来月份继续保留断线；这些绘图规则都不改变实际数据仍为 `null` 的语义。

### 8.2 偏差文案

- 收入：实际高于计划为有利，低于计划为不利；
- 支出：实际低于计划为有利，高于计划为不利；
- `PLAN_LINKED + ACTUAL_ONLY` 保留计划外事实语义；
- `MANUAL` 项目进入实际汇总与排名，但没有计划基准，因此不生成偏差。

颜色只是辅助，徽标和文字必须表达含义。

### 8.3 储蓄率

当前月和历史月只标注“相差 X 个百分点”和“计划完成率 X%”，均基于该月冻结计划。配置预算页的预计储蓄率由下月周期规则和专项分配派生，不参与历史比较。

收入为零时显示 `N/A` 并说明分母不足。

### 8.4 图表

至少提供收入、支出、结余和储蓄率历史趋势；项目较多时优先排序横条图。图表旁保留数值表或可访问文本，不能只靠图形。

## 9. 下月预算投影

该区域只出现在“配置预算”页，是周期规则启用后的下月增强分析。没有周期规则时显示引导空状态，不展示 `0.00` 结果。启用后展示：

```text
预计收入 = 固定收入 + 浮动收入
预计支出 = 必要支出 + 固定承诺 + 自主性预算
预计储蓄 = 预计收入 - 预计支出
预计储蓄率 = 预计储蓄 / 预计收入
```

PAYMENT 项按月均等价计入。预计储蓄为负时明确标注预计缺口，不截断为零；收入为零时储蓄率显示不可计算。固定承诺占稳定收入比例和稳定收入覆盖倍数作为精确数据中的辅助指标。

## 10. 设置

设置页包含彼此独立的财务设置和软件更新卡片。已有月度数据后本位币保持锁定；汇率变更只影响后续新建快照与下月规则投影。当前汇率区提供“启动时自动更新”开关，默认关闭；开启后每次打开应用都尝试执行与手动按钮相同的官方汇率更新，网络失败不阻止进入应用。

软件更新卡片显示当前版本和上次检查，并提供默认开启的“启动后自动检查”开关。启动检查只在财务启动完成后后台执行一次，失败不弹出全局错误；手动检查必须反馈“已是最新”或具体的网络、超时、清单、架构错误。发现更新后，全局只显示不打断操作的提示条。

“下载并安装”需要第二次确认并提醒先保存正在编辑的内容。下载阶段显示字节/百分比并允许取消；进入验签后不再允许取消。签名或应用身份验证失败时现有 `.app` 不变。安装完成只显示重启对话框，不自动退出；默认焦点落在“稍后”，用户也可从设置页再次发起重启。

## 11. 错误与可访问性

- 每个输入错误靠近对应字段；
- 业务错误使用可理解文案，未知错误不泄露 SQL、路径或堆栈；
- 对话框有标题、关闭按钮、键盘焦点顺序和清晰主操作；
- 所有输入都有可访问标签；
- 状态不用颜色单独表达；
- 表格、图表和按钮在窄窗口可重排；
- 侧栏换页只使用短促淡入和轻微位移，首帧前重置滚动位置；
- 尊重减少动画系统设置。

## 12. 关键验收旅程

1. 首次启动直接进入总览 -> 月度执行添加“本月工资”临时类目 -> 从详情添加收入 -> 总览生成实际报表；
2. 创建 1 月 31 日 PAYMENT 计划 -> 预览 2 月末与 3 月 31 日支付日；
3. 在支出项目添加支出与退款 -> 净额、偏差和分析自动变化；
4. 不设置长期计划直接添加临时类目和本月支出 -> 实际汇总不制造计划偏差；
5. 在无计划快照月份关联计划添加退款 -> 建立“计划外实际”项目 -> 后续初始化原位提升且条目不丢；
6. 打开条目编辑或删除确认 -> 详情抽屉保持可见 -> 在上层对话框完成或取消；
7. 删除临时类目 -> 二次确认 -> 类目及条目消失，预算类目不受影响；
8. 删除有历史的计划 -> 历史仍可查看但不能新增条目；
9. 在“配置预算”保存周期规则 -> 下月预算概览与支出占比刷新 -> 当前月和历史月报表不变化。
10. 启动后台检查更新失败 -> 仍可立即使用财务页面 -> 手动检查时看到可理解错误。
11. 发现稳定版 -> 二次确认下载 -> 验签和原子安装 -> 选择稍后或立即重启；任一失败均保留原应用和财务数据库。

## 13. 专项流程

专项页面提供列表、名称/备注搜索和进行中/归档筛选。新建专项只要求名称与本位币总预算，保存后分别展示总预算、已分配、未分配、实际净支出及净剩余。

月分配明确选择月份、三类支出之一和金额。当前月保存前提示立即形成不可改写的快照；已有冻结分配只读，未冻结的未来分配可编辑和删除。分配额度不足时解释总预算约束；不要求用户为未分配池选择技术分摊方式。

实际编辑器选择发生月份、类别、日期、支出/退款、币种、正金额、可选明细组和备注。专项页与月度页共用同一实际；已有实际不可改挂月份或类别，编辑保留原汇率快照。跨月退款在退款发生月记录，允许超支、负净额和归档后的晚到调整。

详情以独立内部滚动表展示月分配、实际条目、月份分析和明细组分析。窄窗口把项目列表置于详情上方，摘要与操作重排；财务列保留可横向滚动。归档不删除预算或事实，不把余量自动滚入其他月份。

“配置预算”分别显示周期月均支出和专项下月分配的构成。没有周期规则但存在专项下月分配时也显示正式预算概览。月度专项类目提供返回专项入口，正式分配计入计划基准；无分配的仅实际类目保持无基准语义。
