# Aplena 信息架构与用户流程

## 1. 体验目标

Aplena 的体验不应像电子表格或传统记账软件。用户不需要理解数据库、汇率快照、摊销或
查询刷新，只需要理解：

- 我计划了什么；
- 本月系统替我准备了什么；
- 哪些实际值还没确认；
- 计划和实际哪里不同；
- 新的长期承诺是否在安全范围内。

设计原则：

1. 新月份无须用户主动创建；
2. 正常月份只编辑少量发生变化的实际值；
3. 空值、零值和计划值不能混淆；
4. “超支”和“少收入”使用业务文案，而不是只显示正负号；
5. 先给结论，再允许用户查看组成和公式；
6. 图表不是数据的唯一表达，始终有数值和文本替代；
7. 历史补录、未来冻结、删除和恢复都必须显式确认。

## 2. 信息架构

桌面端使用固定侧边导航：

```text
概览 Dashboard
本月 Monthly Plan
长期计划 Long-term Plan
历史 History
分析 Analytics
设置 Settings
```

全局顶部区域显示：

- 当前页面标题；
- 当前操作月份；
- 本位币；
- 自动保存或错误状态；
- 备份入口。

历史月份选择是页面状态，不改变当前自然月的自动初始化行为。普通浏览未来月份同样不触发
初始化。

## 3. 首次使用

### 3.1 引导步骤

1. 欢迎与产品边界：说明不是逐笔记账工具；
2. 选择本位币；
3. 设置最低目标储蓄率；
4. 维护需要使用的其他币种和当前汇率；
5. 创建第一个长期计划；
6. 查看本月初始化预览；
7. 进入 Dashboard。

本位币行自动创建且汇率固定为 1。最低目标储蓄率旁展示示例，不把建议值描述为财务建议。

### 3.2 空状态

没有计划时 Dashboard 不显示全零“健康”状态，而显示：

```text
还没有长期计划
添加收入和支出后，Aplena 才能计算本月计划与财务承载能力。
```

当前月没有应计项目但存在计划时，显示“本月没有需要计入的项目”，并允许查看长期计划。

## 4. 长期计划页面

### 4.1 列表

默认按收支方向和类别分组，显示：

```text
项目名称
类别
原币金额
计入模式
周期
月均负担
首次/最后计入月份
状态
```

“状态”只由日期派生：未开始、生效中、已结束。数据库不保存 Enabled。

月均负担对两种模式都显示，用于帮助用户理解长期承载影响。PAYMENT 项目同时显示下一次
预计支付月份。

### 4.2 新建和编辑表单

字段顺序：

1. 项目名称；
2. 类别；
3. 计划金额和币种；
4. 计入模式；
5. 周期（月）；
6. 首次计入月份；
7. 最后计入月份，可空；
8. 备注。

类别确定后，以只读辅助文本显示“收入”或“支出”，不提供可编辑交易类型控件。

计入模式使用两张可选择说明卡，而不是抽象下拉框：

```text
月度均摊
每个有效月份记录月均负担，适合观察长期承载能力。

按支付月计入
只在付款月份记录完整金额，适合观察实际现金支付节奏。
```

字段标签随模式变化：

| 字段 | AMORTIZED | PAYMENT |
|---|---|---|
| `start_month` | 首次均摊月份 | 首次支付月份 |
| `end_month` | 最后均摊月份 | 最后允许支付月份 |
| `period_months` | 分摊周期 | 支付周期 |

表单底部实时显示只读预览：

```text
月均负担：¥100.0000
未来 12 个月计入：2026-06 ¥1,200（PAYMENT 示例）
承载能力影响：每月减少 ¥100.0000
```

预览由后端领域命令计算，前端不自行复制公式。

### 4.3 保存后的当前月行为

新建计划成功后，应用自动检查当前自然月：

- 应计且未生成：创建月度项目并显示通知；
- PAYMENT 且本月非支付月：不创建，说明下一次支付月份；
- 当前月已有同来源快照：跳过，不覆盖；
- 缺少汇率：计划仍保存，但当前月自动初始化失败并提供“前往汇率设置”。

最后一种情况必须明确展示为未完成状态，不能静默失败。

编辑已有计划时显示提示：“更改只影响尚未生成的月份”。不提供“同步全部历史”选项。

### 4.4 停止与删除

“停止”是推荐操作，用户选择最后计入月份。删除需要说明：

- 历史月度快照会保留；
- 来源关联会被移除；
- 删除不能用于修订历史。

删除前展示项目名称和已关联历史月份数量，避免只使用通用“确定删除吗”。

## 5. 月度自动初始化体验

### 5.1 正常启动

自动初始化在后台快速执行，页面用稳定状态表示：

```text
正在准备 2026 年 8 月计划…
已准备本月计划：新增 12 项，已有 3 项，排除 4 项
```

成功通知不阻塞用户。`created = 0` 且没有错误时不反复弹窗。

### 5.2 失败

错误必须可操作。例如：

```text
本月计划尚未完整生成
USD 缺少相对 CNY 的汇率，2 个项目尚未生成。
[前往汇率设置]
```

事务回滚意味着错误发生时不能显示“部分成功”。修复后自动或手动重试同一幂等命令。

### 5.3 历史补录

历史页面发现月份缺口时只显示“补录”入口，不自动创建。确认页包含：

- 目标历史月份；
- 将使用的有效计划；
- 已存在和将创建的项目；
- 当前汇率及“这不是历史汇率”的明确警告；
- 可选的本次临时汇率覆盖；
- 最终转换金额预览。

临时汇率只参与本次计算，不新增历史汇率表。

### 5.4 未来初始化

普通未来浏览保持只读预览。用户点击“冻结为月度计划”后展示：

- 冻结后后续计划和汇率变化不会更新该月份；
- 将创建和跳过的项目；
- 当前汇率；
- 二次确认。

## 6. 本月页面

### 6.1 表格结构

按类别折叠，默认展开存在重要偏差或未录项目的分组：

```text
项目 | 口径 | 计划 | 实际 | 状态 | 偏差 | 备注
```

系统字段只读。`actual_amount` 和 `note` 支持键盘操作和行内保存。

实际金额状态：

- 空白且显示“未录入”；
- 零值显示格式化的 0，并标记“已确认”；
- 非零值显示“已更新”；
- 保存中、已保存和失败有非颜色状态。

不能用 placeholder `0` 表示空实际金额。

### 6.2 比率和偏差

- 收入项目：显示达成率、“多收入”或“少收入”；
- 支出项目：显示预算使用率、“超支”或“节省”；
- 计划为零：比率显示 `N/A`，仍显示金额差；
- actual 为 NULL：不计算完成率或偏差。

AMORTIZED 行解释“实际应填写归一化月均负担”；PAYMENT 行解释“实际应填写本支付月发生
金额”。

### 6.3 批量确认

入口包括：

- 确认当前类别未录项；
- 确认整月未录项。

确认对话框展示即将填充的条数和计划总额，并明确“不会覆盖已填写项目”。完成后
Dashboard 和图表自动更新。

## 7. Dashboard

从上到下排列：

### 7.1 月份和完整度

- 当前操作月份；
- 本月自动初始化结果；
- 实际金额完整度 `entered / total`；
- 数据未完整时的“当前已录”标签。

### 7.2 四项总览

| 指标 | 计划 | 实际 | 解释 |
|---|---:|---:|---|
| 总收入 | 金额 | 当前已录/最终 | 多收入或少收入 |
| 总支出 | 金额 | 当前已录/最终 | 超支或节省 |
| 净结余 | 金额 | 当前已录/最终 | 改善或恶化 |
| 储蓄率 | 比率 | 当前已录/最终 | 百分点差和可用时的目标完成率 |

### 7.3 财务承载能力

优先展示两个透明金额：

1. 保持现有自主预算时的新增长期承载能力；
2. 压缩自主预算后的极限承载能力。

随后展示固定承诺率、基础责任覆盖率和浮动收入上行。信息图标展开公式、所用最低目标
储蓄率以及“所有计划已按月均金额折算”的说明。

不使用未经验证的单一健康分数。分母为零时显示 `N/A` 和原因。

### 7.4 重要偏差

默认排序：

1. 未录实际；
2. 支出超支；
3. 收入不足；
4. 绝对偏差较大的其他项目。

用户可以直接跳转到对应月度行。

### 7.5 图表

- 收入与支出结构：固定的 2–3 个类别可使用环形图；
- 项目占比：默认排序横向条形图；
- 财务趋势：实际收入、实际支出、实际结余；
- 储蓄率趋势：计划与实际折线。

实际数据不完整的月份使用虚线、空心点和文字提示，不能只依赖颜色。ECharts 启用 ARIA
描述，并在图表旁提供同数据的摘要或表格入口。

## 8. 历史与分析

历史页以月份为主，显示：

- 初始化状态或缺口；
- 实际完整度；
- 总览；
- 分类汇总；
- 项目明细；
- 计划与实际。

用户可以修正历史实际金额和备注，但系统快照字段保持只读。修正后所有派生分析自动变化。

分析页支持月份范围和计划/实际切换。不能把不同本位币的月份合并；MVP 通过本位币锁定
从源头阻止此情况。

## 9. 设置

### 9.1 常规

- 本位币：首次快照后显示锁定说明；
- 最低目标储蓄率；
- 当前操作月份；
- 显示语言和金额格式（如在 MVP 中实现，只影响展示）。

### 9.2 汇率

显示：

```text
1 USD = 7.25000000 CNY
更新时间
被多少长期计划引用
```

本位币汇率只读为 1。删除被引用币种时给出引用列表，不自动修改计划。

### 9.3 数据

- 创建完整备份；
- 检查并恢复备份；
- 导出 CSV；
- 查看数据位置时只通过受限系统操作，不暴露任意目录权限。

## 10. 重置未开始月份

只有该月所有实际金额均为 NULL 时显示入口。流程：

1. 展示将删除的快照数量和月份；
2. 说明重新初始化会读取当前计划和汇率；
3. 创建恢复点；
4. 用户二次确认；
5. 删除指定月份并重新执行初始化；
6. 显示创建、跳过和排除结果。

已存在零或非零实际金额时入口不可用，并解释应通过实际修正而不是重建历史。

## 11. 无障碍与视觉语义

- 所有输入有可见标签、错误文本和键盘焦点；
- 错误、成功、超支和节省不只用颜色表示；
- 表格可使用键盘逐单元格导航，但保存状态不会抢走焦点；
- 金额默认右对齐并使用等宽数字；
- 图表提供 ARIA、图案或线型差异和数据表替代；
- 动效遵守 reduced-motion；
- 最低正文和关键数字对比度达到 WCAG AA；
- 屏幕阅读器读出币种、数值和状态，不只读符号。

## 12. 关键用户流程验收

1. 首次设置后无需手动点击即可得到当前月快照。
2. 新建季度 PAYMENT 项目时预览正确支付月份，非支付月不创建空行。
3. 新建年付 AMORTIZED 项目时当前月生成十二分之一金额。
4. 编辑长期金额后已有月度计划保持原值，未来预览使用新值。
5. actual 为空时 Dashboard 标记不完整；填 0 后完整度增加但金额仍为 0。
6. 批量确认只填空值，保留用户已填的 0 和其他金额。
7. 打开历史和未来月份不发生写操作。
8. 补录历史时必须看到汇率风险和最终金额预览。
9. PAYMENT 项目的支付峰值出现在月度执行中，但承载卡按月均金额计算。
10. 所有比率不可定义时显示原因明确的 `N/A`。
