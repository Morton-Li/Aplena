# 产品与使用流程

本文说明当前代码的产品行为与交互约定，数据库基线为 schema 10；不代表某个公开发行版本已经完成验收。计算与事务细节见[架构与领域](architecture.md)，存储与兼容性见[数据库](database.md)。

## 产品定位与边界

Aplena 是单用户、单账本、本地优先的个人财务桌面应用，以月份组织实际收入、支出、退款和冲减，并用冻结计划与下月预算辅助决策。用户可以直接记录本月事实，无须先建立周期规则，也无须每天记账。

当前主导航与用途：

| 页面 | 用途 |
|---|---|
| 总览 | 当前自然月指标、计划对比、重要偏差、分类结构和历史趋势 |
| 月度执行 | 当前月录入，或从历史报告明确进入所选月份调整 |
| 专项 | 跨月事项的总预算、月分配、支出退款和分析 |
| 借贷 | 双向本金往来、分期计划、实际还款回款和现金流 |
| 历史报表 | 已有月份、年度汇总与月度详细报告 |
| 配置预算 | 下一个自然月的预算投影与周期规则维护 |
| 设置 | 本位币、汇率、启动汇率刷新偏好及软件更新 |

当前不提供云账户、银行同步、交易导入、账户余额管理、商户系统、自由流水或会计分录；没有内置备份恢复、可读导出及独立“财务分析”页面。情景模拟、静态数据库加密等候选能力不能当作已有功能。

## 第一次使用与共同口径

首次启动没有向导，默认创建人民币本位币并进入总览。前往“月度执行”，添加临时类目，再从详情添加第一笔收入或支出，即可形成实际报表。

- 本位币在尚未形成月度项目、专项或借贷时可修改；存在上述数据后锁定。单纯保存周期规则不形成历史财务事实。
- 类别固定为固定收入、浮动收入、必要支出、固定承诺支出、自主性预算；前两类属于收入，其余属于支出。
- 金额保存到分，汇率保存八位精度。退款和冲减用条目类型表达，录入金额仍为正数。
- 月度类目没有待确认、处理中、已完成等状态，也没有“确认零实际”操作。
- 没有实际条目时实际为未知，精确数据使用“—”；有条目且正负效果相抵时才是 `0.00`，净额也可以为负。
- 计划金额、分类、币种、支付日等月度快照字段形成后冻结；后来更改规则、汇率或删除规则不会回算已有计划。

## 月度执行与历史调整

### 进入月份与补齐预算

应用在启动及运行中的当前月检查中幂等补齐当月预算。新增或修改规则本身不触发当月快照写入。只浏览历史或未来月份不会写数据；已有月份可直接查看，缺失预算经明确确认后才初始化。

月度执行显示可补齐的规则数量。有已有项目时使用“补齐该月规则”，只补缺项，保留已有快照与实际。计划外实际形成的容器若后来符合正式预算条件，可以原位提升，保留项目身份与全部条目。按支付月份确认的规则在非支付月可以不生成计划项目；空月不是错误。

历史报表提供“调整该月数据”“调整条目”及“补录历史月份”入口。进入工作台后可保存普通实际、维护临时类目及月度备注；生成历史计划快照需确认，并可输入只用于此次初始化的临时汇率。当前汇率不一定代表历史汇率，临时覆盖不会改写汇率设置。未来月份的初始化同样需要确认快照冻结含义。

### 临时类目与实际条目

“添加临时类目”只要求名称、财务类别和可选备注，不同时创建实际。保存后打开详情，通过上下文入口继续录入。临时类目的计划金额为零，进入实际汇总但没有预算基准，不产生虚构的偏差或完成率。

详情展示只读计划、实际净额、条目数、偏差和来源；月度工作台支持名称/备注搜索、类别/方向/偏差筛选及排序。支出项目使用“支出 / 退款”，收入项目使用“收入 / 冲减”。

录入约定：

1. 日期必须在所属月内；新条目默认当天，跨月调整时默认该月第一日，编辑保留原日期。
2. 金额必须大于零、最多两位小数。可输入带 `+ - * /` 与括号的运算式；各数值项最多两位小数，按运算优先级精确计算并在最终结果四舍五入到分，只保存结果。
3. 空金额、非法运算式、除零及无效结果在点击保存时给出字段旁错误，不能只用无提示的禁用按钮代替校验。
4. 新建外币条目展示本次换算基准、来源和日期；保存原币金额与独立汇率快照。编辑沿用原币种和原汇率，后续汇率刷新不回算旧事实。
5. 用户和自动条目可编辑、删除；旧版迁移聚合条目只读。删除需应用内确认；上层编辑/确认对话框打开时详情抽屉保持可见。

只有用户建立的临时类目提供整类删除，确认时说明其条目数与不可撤销性，类目及条目在同一事务删除。预算类目和专项、借贷关联类目使用各自入口维护。删除周期规则会保留已生成的快照和实际；脱离已删除规则的类目不能新增条目，已有可编辑条目仍可调整。

保存实际后，总览、月度和历史查询自动刷新；用户不直接编辑聚合总额。借贷利息费用关联条目统一从借贷详情调整。

## 配置下月预算与周期规则

“配置预算”始终面向系统计算的下一个自然月，不接受独立储蓄目标。页面并排展示预算概览与支出类型占比，窄窗口上下排列。预算是前瞻结果，不写入本月，不混入当前月或历史月的计划比较。

### 规则表单与两种模式

规则包含名称、类别、金额、币种、周期月数、计入模式、开始日、可选结束日和备注。名称规范化后唯一；金额允许零，周期必须为正整数，结束日不得早于开始日。新规则默认从下月第一日开始，收支方向随类别确定。

| 模式 | 月度计划行为 |
|---|---|
| 按月均摊 `AMORTIZED` | 有效期与目标月有交集即计入完整月均负担，不按天数折算 |
| 按支付月份确认 `PAYMENT` | 以开始日为原始支付日锚点，每隔周期月计入完整金额 |

支付锚点遇短月取月末，后续长月恢复原日。例如从 1 月 31 日开始月付，依次为 1 月 31 日、2 月末、3 月 31 日；支付日超过结束日便不计入。两种模式在下月投影中均使用月均等价负担。

保存前由后端预览有效性、目标月是否计入、计划支付日、本位币金额、月均等价与下一笔自动入账日期。停止后续规则通过设置结束日完成；删除前提示历史快照和实际保留。

### 预算来源与指标

下月预算合并三类来源，各项只计一次：

- 周期规则：按当前汇率换算后的月均等价收入和三类支出；
- 专项：直接加入下月明确分配额，不包含总预算与未分配池；
- 借贷：按下月到期期次的剩余利息及费用计入收入或支出，不把季度、年度还款均摊。

```text
预计储蓄 = 预计收入 - 预计支出
预计储蓄率 = 预计储蓄 ÷ 预计收入
含借贷的预计现金净结余 = 预计储蓄 - 待还本金 + 待收本金
```

待还和待收本金独立列示，不能作为收入支出重复计算。没有周期规则但有专项月分配或借贷到期利息费用时，仍可显示预算。没有预算来源时概览显示引导空状态；预计储蓄为负时显示缺口，收入为零时比例不可计算。

支出饼图只比较三类支出，以本位币金额计算，不把收入放进同一分母；零金额不生成扇区。固定承诺占稳定收入比例和稳定收入覆盖倍数作为辅助指标。图表可翻转查看精确数据，背面在固定高度内滚动，不拉伸同一行相邻卡片。

### 自动入账

自动开关按规则设置，默认关闭。开启及后续规则版本从下个月生效；关闭立即停止未执行记录，缩短结束日期也会立即阻止超出有效期的未入账发生，已有实际保留。开启时金额必须大于零。

- `PAYMENT` 使用规则开始日作为支付锚点；月均摊规则使用单独的首次实际收支日。每月规则可默认下月第一日或更晚的规则开始日，多月均摊必须明确首次日期。
- 自动记录按原周期写入一次完整金额，不能把月均预算额当作真实支付额。调整有效期时保留已选月均摊收支日作为周期锚点，保存前可查看下一次日期。
- 应用在启动、回到前台及窗口可见时每分钟检查，只处理当前月已到期事项。关闭应用时无后台写入，重开不自动追补遗漏历史月份。
- 到期记录直接成为正式实际，带自动来源标识。外币使用当次保存的汇率，缺失汇率时显示失败，补齐后自动重试。
- 发现同类目已有手动实际时，不按金额猜测，提供关联所选记录、跳过本次、明确另建一笔三个动作。既有预算类目与冻结版本类别不一致时也会提示冲突，不能自动改写类别。
- 删除自动条目后保留该次发生记录，后续检查不会重建。历史月份失败需手动补录。

月度执行只在检查/读取失败、发生记录失败或冲突时显示提示；异常解除后提示消失。规则保存成功但自动策略保存失败时，界面说明已保存的部分并允许重试。

## 专项

旅行、装修等跨月事项可建立专项，仅需名称和本位币总预算。列表支持名称/备注搜索及进行中/归档筛选，详情分别显示总预算、已分配、未分配、实际净支出和净剩余。

月分配明确指定月份、三类支出之一及金额，分配总额不得超过总预算。当前月保存分配即形成冻结快照；已有冻结分配只读，尚未形成快照的未来分配可修改、删除。未分配额保留在项目预算池，不自动摊入月份，也不在归档后自动滚入其他月份。

专项实际填写发生月、类别、日期、支出/退款、币种、正金额、可选明细组和备注。专项与月度执行共用同一条实际，月度类目提供返回专项入口；已有实际不能改挂月份或类别，编辑保留原汇率快照。

- 有明确月分配的类目进入正式计划基准，无分配的实际容器保持无基准语义。
- 跨月退款计在退款发生月，允许负净支出及超过总预算的实际。
- 未分配预算与“总预算减实际净支出”的净剩余分别计算。
- 归档保留预算和全部事实，允许晚到实际及纠错。
- 详情按月份和明细组分析；长表独立滚动，窄窗口重排并保留财务列横向滚动。

## 借贷

借贷区分“我需偿还”和“待他人归还”，同一对方可有多笔合同，当前使用本位币。新建时选择完整发生记录，或从期初剩余本金开始跟踪；期初录入不虚构更早的现金流。

“我需偿还”和“待他人归还”均将追加本金与实际归还合并为一张往来表，按日期倒序列示，保留各自的类型、本金、利息、费用与编辑删除入口；借贷页使用独立的紫色主题。

合同详情可追加借入/借出，分别记录实际日期、正本金和备注，并支持编辑删除。追加本金增加余额，按发生月进入本金现金流；若分期计划未还本金与余额不一致，会标记待核对，核对前暂停预算预测。

计划支持日、月、季度、年及每 N 周期，采用等额本金、等额本息或手动逐期计划。自动计算填写明确的每期利率，先预览再保存，不暗中换算年利率。未约定到期日不判断逾期，到期也不会自动记作已还。

实际还款/回款分别填写本金、利息、费用和发生日，可按某期余额填入，预览并调整期次分配后保存。支持部分、跨期及提前归还；后续计划用新版本接续，保留历史计划与全部实际。实际记录可编辑、删除，跨月纠错同步更新相应月份。

本金只进入余额和现金流，利息费用形成月度收支关联事实，从借贷详情统一调整。总览和历史另列本金现金流，下月预算另列待还、待收本金及现金净结余。同项借贷若已有周期规则，须显式调整，避免重复预算。

新建或编辑资料可选择启用利息，支持按剩余本金单利、按周期复利、每周期固定利息，以及日、月、季度、年四种周期。利率明确对应所选周期；可独立指定不早于建档日期的起息日。起息日计息，截至日不计息，追加与归还当日先调整本金；不足周期按该周期实际天数折算，月末和闰日保留原日期锚点，最终四舍五入到分。复利只在完整周期结束时将未付利息加入下一周期基数，固定额在本金结清后停止计息。

详情展示应计、已付与待付利息估算；实际收付窗口可按发生日计算并填入待付利息，编辑时排除该笔旧收付。修改或关闭规则不改写实际或分期，估算不自动入账、不重复加入预算。已付超额部分保留为抵扣；计息超出金额范围时仍可打开合同并修正规则。

本金、有效计划利息费用及待付利息估算结清后可归档；归档后仍可纠正晚到事实，不删除合同历史。

## 总览、月报与年度报告

核心指标为收入、支出、净结余与储蓄率；净结余为收入减支出，储蓄率为净结余除以收入。分母为零或不足时显示不可计算。实际净额由增加条目减退款/冲减实时派生，不要求项目确认完成。

项目偏差使用“实际减计划”：收入高于计划通常有利，支出高于计划通常不利，以文字和徽标说明业务效果，颜色仅辅助。没有正式计划基准的类目进入实际汇总与排名，不制造计划偏差。储蓄率比较使用该月冻结计划的百分点差异和计划完成率，不与下月预算混用。

总览固定当前月，包含计划对比、重要偏差、分类结构、近期收支及储蓄率趋势。精确指标与数值表保留空值；总览柱状图仅在绘图层把缺失实际放到零轴，趋势图对已结束月份的缺失点按零绘制，当前和未来月保留断线。这些展示规则不生成实际记录。

历史报表按年份展开已有月份：

- 月度报告展示完整收支、计划执行、分类结构、项目排名和偏差，可进入整月或项目实际调整。
- 月报项目占比饼图支持收入/支出及计划/实际切换，只用正金额合计作分母；负额、零额和未录入项目仍在明细中保留。
- 年度报告汇总已收录月份的全年收支、冻结计划、十二月趋势和分类结构，并提供跳转月报的月度明细。
- 年度储蓄率用全年净结余除以全年收入，分类占比用年度金额重新计算，不平均月度比例；缺失月份和未录入实际保持为空。

图表保留对应精确数据或可访问文本；翻转后隐藏面不可聚焦，并遵循系统减少动画偏好。

## 设置、联网与软件更新

财务数据保存在当前操作系统用户的应用数据目录，不上传云端。网络用于欧洲央行参考汇率和 GitHub 软件更新；离线仍可使用本地功能及已保存备用汇率。SQLite 文件尚未静态加密，使用系统用户权限限制访问；设备保护建议启用 FileVault。数据兼容、迁移失败和高版本数据库处理见[数据库](database.md)。

汇率口径为“1 单位原币 = N 单位本位币”。设置支持手动刷新官方参考汇率及维护备用汇率；“启动时自动更新”默认关闭，开启后每次启动尝试刷新，失败不阻断使用。修改本位币前需具备换算所需汇率，折算后的备用汇率保留来源与日期。汇率更新影响后续快照、条目和预算，不修改已有计划或实际的换算快照。

软件更新与财务设置独立，显示当前版本、上次检查、可用稳定版、说明及下载大小。“启动后自动检查”默认开启，在财务启动完成后后台执行，失败保持静默；手动检查明确反馈结果。发现更新使用不打断操作的提示条。

“下载并安装”需明确确认，并提醒保存编辑内容；下载时展示进度并允许取消，进入验签后不可取消。安装先验证 updater 签名，再校验应用身份、版本、架构与代码签名；失败保留原应用。成功后提示重启，默认焦点为“稍后”，不自动退出。平台、签名限制和发行验证见[开发与发行](development.md)。

## 交互与验收约定

字段错误靠近输入；业务错误使用可理解文案，未知错误不暴露 SQL、路径或堆栈。对话框具备标题、关闭方式与焦点管理，输入具备可访问标签，状态不单凭颜色表达，窄窗口可重排并尊重减少动画设置。

维护产品行为时至少覆盖受影响旅程：首次临时类目与实际、退款冲减和空值、月末支付锚点、历史补录与快照不变、删除规则后历史保留、专项共享事实、自动记录删除不重建/冲突处理、借贷本金及利息分离、月报年度汇总、离线与更新失败。具体检查命令见[开发与发行](development.md)，设计取舍见[设计决策](decisions.md)。
